# 2026-09-16 · 모바일에서 "내 서재" 책 탑이 패널 밖으로 깨지던 문제

내 서재(`/my`) 상단 프로필 패널의 쌓인 책 탑이 좁은 화면에서 패널 오른쪽 경계를
넘어가 잘려 보였다. 받침대까지 삐져나와 화면에 가로 스크롤이 생겼다.

## 원인 (Phase 1 — 근본 원인 조사)

`BookStack.vue`가 **책등 폭을 제목 길이로 계산한 고정 px**로 인라인 style에 박고 있었다.

```
spineWidth = clamp(72, 제목길이 × 8.8 + 18, 210) ± 4   // px
baseWidth  = max(130, 가장 넓은 책등) + 16              // px
```

데스크톱에선 자리가 남아 문제가 없다. 모바일에선 사정이 다르다.

```
375px 뷰포트 → wrap 좌우 16 + panel 좌우 16  →  패널 안쪽 ≈ 311px

필요한 폭:  완독 숫자(nowrap, ~150px) + gap 22px + 탑(최대 226px) = 398px
```

`.stack-widget`은 flex이고 flex 항목의 기본 `min-width: auto`는 **내용 폭 아래로
줄어들지 않는다**. 즉 폭이 모자라도 탑이 줄 방법이 없어서 그대로 밖으로 밀려 나갔다.
숫자 쪽은 `white-space: nowrap`이라 역시 안 줄어드니, 넘치는 몫은 전부 탑이 떠안았다.

스크린샷의 "리팩토링 데이터베이스(위키북스 …)" 책등이 패널 경계에서 잘린 것이 그 결과다.

## 고친 방식 (Phase 4)

폭을 **두 갈래로 쪼갰다**. 탑 전체가 쓰고 싶은 폭(px) 하나 + 그 안에서 각 책등이
차지하는 **비율(%)**. 그러면 CSS가 폭 한 줄만 클램프하면 탑이 통째로 줄어든다.

- 기하 계산을 컴포넌트 밖 순수 함수로 분리 → `shared/utils/bookStack.ts`
  (`layoutStack()` → `{ width, spines[{ widthPercent, color }], overflowCount }`)
- `.bookstack { width: min(var(--stack-w), 100%); min-width: 0 }`
  — `min-width: 0`이 없으면 위의 `min-width: auto` 때문에 클램프가 무효가 된다.
- 책등은 `width: N%`, 받침대는 `width: 100%`
- ≤640px에서는 숫자와 탑을 **위아래 두 줄로** 분리 — 한 줄을 나눠 가지면 nowrap인
  숫자가 자리를 다 먹고 탑만 짓눌린다. 줄을 나누면 탑이 패널 폭을 통째로 쓴다.

비율로 바뀌었으므로 **좁아져도 책마다 길이가 다른 "손으로 쌓은 탑" 모양이 그대로 남는다.**
가장 넓은 책등은 항상 받침대보다 좁다(받침대 여유 16px → 최대 약 93%).

## 검증

- `tests/bookStack.test.ts` 6건 신규 — 모듈이 없을 때 실패(RED) 확인 후 구현
  - 모든 책등 비율 ≤ 100%, 가장 넓은 책등도 받침대보다 좁음
  - 폭을 절반으로 클램프해도 상대 크기 유지
  - 최대 9권 + `+N권`, 빈 서재에서도 폭 > 0
- 전체 테스트 251건 통과, `nuxt build` 성공
- 빌드 산출 CSS에 `width:min(var(--stack-w),100%)` 확인

## 배운 것

flex 안에서 "줄어들어야 하는" 항목에는 `min-width: 0`이 사실상 필수다.
`max-width`나 `min()`을 걸어도 `min-width: auto`가 조용히 이긴다.
