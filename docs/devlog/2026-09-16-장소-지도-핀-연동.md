# 2026-09-16 · 장소 화면 지도 개선 (핀 번호·목록 연동·내 위치)

장소 화면에 대한 QA 지적 3건을 체계적 디버깅으로 원인부터 잡고 고쳤다.

## 지적 사항

1. 우측 목록에서 장소를 눌러도 지도가 아무 반응이 없다
2. 목록은 1·2·3·4인데 지도에는 5·7·8·10·11·12가 보인다
3. "내 위치"가 안 먹힌다 — 자꾸 엉뚱한 건물(이우홀딩스)에 찍힌다

## 원인 (Phase 1 — 근본 원인 조사)

### #2 번호 불일치 — 원인 두 가지가 겹쳐 있었다

**(a) 핀이 서로를 덮고 있었다.** 상위 3곳이 주소가 전부 같다(`삼성1로 209`).
핀을 목록 순서대로 하나씩 얹으므로 **나중 번호가 앞 번호를 덮는다**. 지도에 5·7·8이
보인 건 순서가 틀려서가 아니라 1·2·3이 그 밑에 깔린 것이다.

**(b) 번호를 매기는 기준이 목록과 지도가 달랐다.** 목록은 `displayList` 인덱스로,
지도는 좌표 없는 곳을 걸러낸 뒤의 인덱스로 번호를 매겼다. 좌표가 (0,0)인 장소가
하나라도 끼면 그 뒤 번호가 통째로 한 칸씩 밀린다.

```
목록:        A(1)  B(2, 좌표없음)  C(3)
예전 지도:   A(1)                  C(2)   ← 어긋남
지금 지도:   A(1)                  C(3)   ← 일치
```

### #3 내 위치 — 코드 버그 1 + 환경 요인 1

**코드 버그:** `locateMe()`가 위치를 잡고 목록을 다시 불러오면
`watch(validPlaces)` → `renderPins()` → `map.setBounds()`가 실행되는데, 이 bounds에
**내 위치가 빠져 있었다**. 앞서 실행된 `panTo(내 위치)`를 뒤늦은 `setBounds`가 덮어써
지도가 사업장으로 되돌아갔다.

**환경 요인:** 데스크톱 브라우저에는 GPS가 없어 Wi-Fi/IP로 좌표를 추정한다. 그래서
웹에서는 늘 같은 엉뚱한 건물로 찍힌다(사용자 확인: **모바일은 정확, 웹만 틀림**).
코드로 정확도를 올릴 방법은 없다.

### #1 목록↔지도 연동
버그가 아니라 없는 기능이었다. 기존엔 마커를 누르면 카카오맵 새 탭이 열릴 뿐이었다.

## 고친 것

### 번호 일치 (`shared/utils/placeKey.ts`)
`toMapPins()` — **거르기 전에** 번호를 매긴다. 목록과 지도가 같은 함수를 쓴다.
장소 식별은 번호가 아니라 `placeKey()`(카카오 장소 id, 없으면 이름) 하나로만 한다.

### 핀 겹침 풀기 — 두 번 갈아엎었다
1. ~~위경도 반올림으로 묶어 원형 배치~~ → 반올림 칸 경계에 걸친 쌍을 놓쳤다(실측 8.9px)
2. ~~픽셀 기준으로 묶어 원형 배치~~ → 서로 다른 무리가 벌어지다 부딪혔다(실측 18.9px)
3. **채택: 쌍 단위 완화(relaxation)** — "모든 쌍이 32px 이상"이라는 조건 하나만 보므로
   무리의 경계와 무관하게 성립한다. 좌표가 완전히 같아도 풀리도록 황금각 미세 오프셋을
   준다(결정론적 — 같은 입력이면 같은 배치).

사업장 마커는 이름표까지 달려 크므로 **움직이지 않는 장애물**로 넣었고, 그래도 라벨
폭(150px)을 원형 여백으로는 다 못 피해서 **z축을 뒤집었다**(핀 > 사업장 라벨).
라벨은 맥락이고 번호 핀은 데이터라 데이터를 위에 둔다.

### 목록 ↔ 지도 양방향 선택
- 카드 윗줄 클릭 → 지도가 그 핀으로 이동, 핀이 커지고 이름표가 붙는다
- 핀 클릭 → 목록이 그 카드로 스크롤(`block:'nearest'` — 이미 보이면 안 튄다)되고 강조
- 카드 윗줄만 버튼으로 뺐다. 카드 전체를 클릭 대상으로 만들면 "카카오맵에서 보기"를
  누르려다 선택이 토글된다.

### 내 위치
- `setBounds`에 내 위치를 포함 → 지도가 사업장으로 되돌아가지 않는다
- `coords.accuracy`를 그대로 노출(`±2.5km까지 벗어날 수 있어요`) — 오차를 숨기지 않는다
- 오차가 500m를 넘으면 **지도 클릭 보정 모드**를 자동으로 연다. 찍은 지점을 내 위치로
  삼고 그 주변을 다시 검색한다. 웹의 부정확한 추정을 사용자가 직접 바로잡는 탈출구.

### 곁다리로 잡힌 진짜 버그
브라우저 검증 중 `kakao.maps.LatLng is not a constructor`가 떴다. `autoload=false`라
`kakao.maps`는 스크립트 onload 직후 존재하지만 `Map`·`LatLng` 클래스는
`kakao.maps.load()` 콜백 뒤에야 채워진다. 그 사이에 목록 응답이 도착하면 터진다.
`sdkReady` 플래그로 **로드 완료**를 조건으로 바꿨다. (기존에도 있던 잠복 버그)

## 검증

- 단위 테스트 19개 추가(`tests/placeMapPins.test.ts`) — 전체 240개 통과
  - 번호 밀림, 좌표 완전 일치, 실측 8.9px/18.9px 겹침, 12개 동일 지점, 장애물 회피,
    결정론성, 원위치에서 과도하게 멀어지지 않기
- Playwright로 실제 앱 구동 검증
  - 목록 번호 = 지도 핀 번호 (1~12 완전 일치)
  - **가려진 핀 0개** (`elementFromPoint`로 확인) — 개선 전엔 6개만 보였다
  - 최소 핀 간격 31.4px, 줌 변경 후에도 32.0px 유지
  - 목록 3번 클릭 → 핀 3번 선택 / 핀 9번 클릭 → 카드 9번 선택·스크롤
  - 내 위치(오차 2.5km 시뮬레이션) → 경고 배너·보정 모드 → 지도 클릭 보정 → 경고 해제
  - 390px 모바일: 가로 오버플로 0, 탭 선택 동작

## 남는 한계

웹의 geolocation 정확도 자체는 못 고친다. 오차를 드러내고 수동 보정을 주는 것이 한계선.
발표 시연은 모바일이 정확하므로 모바일로 하는 편이 낫다.
