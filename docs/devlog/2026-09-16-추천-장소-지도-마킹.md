# 2026-09-16 책벗이 추천한 곳만 지도에 — 사업장 기준점 전달 + 마킹

[[2026-09-16-책벗-후기-근거-보기]]로 근거는 볼 수 있게 됐는데, "장소 보기" 버튼은 여전히 맨
`/places`로만 갔다. 엠시스 근처를 물어봐도 지도는 동탄 본사 기준으로 열리고, 책벗이 고른 3곳이
아니라 반경 전체가 거리순으로 깔렸다. 추천과 지도가 서로 다른 얘기를 하고 있었다.

  `주변 전체 보기` 버튼.

## 설계에서 고른 것

- **좌표는 모델에게 주지 않고 사이드 채널로 받는다.** 지도에 찍으려면 lat/lng이 필요한데, 모델은
  그 값을 쓰지 않는다. 도구 JSON에 넣으면 장소 6곳 × 매 호출마다 토큰만 나간다. 도구가 결과를 한 번
  더 흘려보내게 하니 모델 payload는 그대로면서 주소·거리·placeUrl까지 온전한 `Place`를 쓴다.
- **장소 id를 URL에 싣지 않았다.** 카카오 로컬에는 id 단건 조회가 없어서 `/places`가 id만 받아서는
  장소를 되살릴 수 없다. 같은 SPA 안의 이동이니 객체를 그대로 넘기고, URL엔 "어느 사업장인지 ·
  추천만 볼지"만 남겼다.
- **경로는 서버가 만든다.** 모델이 쿼리를 직접 짜게 하려면 `parse.ts`의 경로 화이트리스트를 열어야
  하고, 그러면 임의 경로를 만들어낼 틈이 생긴다. 모델은 `/places`까지만 말할 수 있게 두고 나머지는
  도구가 실제로 쓴 값으로 채웠다.
- **추천 stash는 메시지에 묶었다.** 전역에 "마지막 추천" 하나만 두면, 대화를 더 이어간 뒤 위로
  스크롤해 예전 버튼을 누를 때 엉뚱한 장소가 찍힌다. 버튼이 메시지에 속하므로 그 메시지의 추천을 넘긴다.
- **이름을 하나도 안 불렀으면 장소는 비우고 사업장만 옮긴다.** 근거 패널은 이때 상위 3곳으로 폴백하지만
  지도는 폴백하지 않는다. 근거는 "참고할 후기"지만 핀은 "책벗이 여길 추천했다"는 주장이라, 틀리면
  성질이 다르다.
- **후기 도구만 쓴 턴은 아무것도 바꾸지 않는다.** `search_reviewed_places`는 DB만 보므로 좌표도 없고
  사업장 인자도 없다. 옮길 기준점 자체가 없어서 `/places` 버튼을 그대로 둔다.
