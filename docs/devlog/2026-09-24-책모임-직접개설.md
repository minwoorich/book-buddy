# 2026-09-24 책모임 직접 개설 — 개설·모집·게시판

설계서 [[../superpowers/specs/2026-09-24-책모임-직접개설-design|직접 개설 설계서]] · 계획 [[../superpowers/plans/2026-09-24-책모임-직접개설|9태스크]] · 전제 [[2026-09-24-책모임-3단계|책모임 3단계]]

브랜치 `feat/club-recruit`, 14커밋(구현 9 + 태스크 리뷰 수정 3 + 최종 리뷰 수정 2). 테스트 490 → 537건, 전부 통과. 빌드 통과.

## 왜

3단계까지의 책모임은 **에이전트만 만들 수 있었다**(완독자 탐지 → 관리자 승인 → 초대). 민우의 지적: "직접 개설하고 글도 쓰고 방도 파고 이런 게 없잖아." 사람이 시작하는 모임을 더하되, 시작만 사람이 하고 그다음(투표·장소·리마인드·종료·후기 요청)은 같은 기계를 타게 했다.

## 결정 (브레인스토밍)

같은 모임·시작만 사람이 / 공개 모집 + 초대 / 모집글 + 모임 안 게시판 / 참여 조건 없음(완독자 표시만) / 관리자 승인 없음 / 사람 모임엔 쿼터 없음(모집 중 1개 상한) / 모집 종료는 개설자가 닫되 기간 만료 안전망(3·7·14일).

## 무엇이 생겼나

- **스키마** — `clubs`에 `origin·created_by·title·description·capacity·recruit_until`(ALTER 6, 기존 행은 `agent`), `club_posts`. 마이그레이션은 추가만.
- **`clubRecruitService`** — 개설(제목 1~40·소개 ≤1000·정원 3~6·기간 3/7/14·**호스트로 모집 중 1개 상한**), 공개 참여(선착순, **초대가 예약한 자리까지 세어** 정원 판정), 참여 취소, 초대(정원 한도, 기존 `club_invited`), **모집 마감**(3명↑ → 미응답 초대 정리 → 아젠다 생성 → 기존 `enterScheduling`), 접기, 관리자 닫기, **모집 만료**(`club:deadlines`에서 3명↑ 자동 조율/미만 취소). `clubService.respond`는 사람 모임에서 자동 전이를 하지 않는다.
- **`clubDeadlines.runAllDeadlines`** — 모집 만료(비동기)와 기존 기한 작업을 한 순서로. `clubService`↔`clubRecruitService` 순환 import를 피하려 별 파일.
- **게시판** — `clubPostRepo`/`clubPostService`: 글·댓글(한 단계), 수락자만, 끝난 모임은 읽기만, 작성자·호스트 삭제(댓글 동반), `club_post` 알림은 **모임당 KST 하루 1건**(링크 `/clubs/:id?posts=YYYY-MM-DD`로 dedup).
- **`clubTitle`** — 사람 모임은 제목, 아니면 『책』 책모임. 알림·카드·상세가 전부 이걸 쓴다.
- **API 12개** + `canViewClub`(멤버·관리자·**모집 중 사람 모임은 누구나**).
- **화면** — `/clubs/new`(책 검색 → 제목 기본값 → 소개 → 정원 → 기간), `/clubs`의 "모임 만들기"와 **"모집 중"** 구획(카드: 제목·『책』·개설자·"1/5명 · 모집 중 D-8 · 완독 1"·소개 첫 줄·"참여할 수 있어요"), 상세의 모집 액션(참여하기/참여 취소/초대하기/모집 마감 → 시간 잡기/모임 접기), 초대 모달(이름·부서 검색, 게스트 제외), **"이야기" 게시판**, 관리자 "진행 중인 모임"(사람/에이전트 배지 + 닫기).

## 리뷰가 잡은 것

| 어디서 | 무엇 | 처리 |
|---|---|---|
| **T4** | **공개 참여가 초대(invited)가 예약한 자리를 무시** — 정원 3에 초대 2 + 공개 참여 1 + 초대 수락 2 = 4명. 계획의 참조 코드 결함 | `join`이 수락 + 초대 대기를 센다 + 재현 테스트 |
| T3 | "사람 모임 respond 테스트가 3명 수락에 도달 안 함" | **기각** — 개설자가 `accepted`로 들어가므로 host+a+b=3, 실제로 도달한다(리뷰어가 호스트를 안 셈) |
| T6 | 다른 모임 글에 댓글 금지 분기가 테스트되지 않음 | 테스트 추가 |
| **T9 / 시각 확인** | **비멤버가 모집 중 모임 상세를 못 열어 "참여하기"가 불가능** — 1단계의 "멤버만" 규칙(아젠다의 동료 리뷰 인용 보호)이 공개 모집과 충돌. 태스크 리뷰 6번이 못 본 걸 헤드리스 브라우저가 첫 시도에서 잡았다 | `canViewClub`: 모집 중엔 아젠다가 없으니 누구나. 순수 함수 + 테스트 5 |
| T9 | 관리자 "닫기" 버튼이 `.actions` 밖이라 네이티브 버튼으로 렌더(스크린샷으로 확인) | 스타일 |

최종 전체 리뷰(opus, `d80f2f6..05fb423`): Critical 0 · Important 6 · Minor 18. Important는 전부, Minor는 값싼 것만 한 번의 수정 파도로.

| 등급 | 무엇 | 처리 |
|---|---|---|
| **I-1** | **한국어 조사가 사람 모임 제목에서 깨짐** — 원래 `『책』 책모임`(받침 ㅁ)만 들어오던 자리 7곳에 `이/을`이 고정. 기본 제목 `『책』 함께 읽기`면 "…함께 읽기이 열리지 않았어요" | `josa(word, '이', '가')` 헬퍼(받침 유무) |
| I-2 | `.ics`와 독서 달력이 아직 `bookTitle` — 아웃룩엔 『책』 책모임, 달력엔 "제목 책모임"(중복 접미어). 태스크 경계를 넘는 누락 | `clubTitle` 적용 |
| **I-3** | **`closeRecruiting`이 `await`(LLM 왕복) 뒤 상태를 재확인 안 함** — 두 요청이 겹치면 `enterScheduling` 2회 → 슬롯 덮어쓰기·투표 요청 2배·LLM 이중 청구 | await 뒤 다시 읽어 `inviting`이 아니면 그대로 반환 + 동시 호출 테스트 |
| I-4 | `adminCancel`이 `proposed`(초대가 나간 적 없는 제안)까지 닫고 `club_canceled`를 보냄 — `rejectProposal`의 "아무에게도 알리지 않는다" 불변식 위반 | 400 가드 |
| I-5 | `runAllDeadlines` 테스트가 전 필드 0만 단정 — `{...rest, recruitExpired}` 순서를 뒤집어도 통과(사전 스캔이 지목한 바로 그 위험) | 실제 만료 1건으로 단정 |
| I-6 | 화면의 "정원 찼나"가 수락자만 셈(서버는 수락 + 초대 대기) — "참여할 수 있어요" 눌렀더니 400 | 양쪽 같은 산술 |
| Minor | 모집 만료 실패가 그날 기한 작업 전체를 삼킴 · 게시판 시각이 브라우저 로컬 · 긴 책 제목이면 기본 제목이 40자 초과로 무조건 400 · 서버 초대가 게스트를 안 거름 · `recruitUntil == now` 경계 테스트 | 동반 수정 |

리뷰가 지적했지만 보류한 것: `CLUB_RULES.minMembers`를 shared로(화면의 "3" 리터럴), 탈퇴자의 글 처리, 게스트 해제 시 호스트 모임 정리, `/api/clubs/recruiting`의 멤버 전체 노출(사내 도구라 수용), `enterScheduling`이 슬롯을 못 찾을 때 참가자 알림(에이전트 모임과 같은 동작).

## 시각 확인

헤드리스 Chrome/CDP로 로컬 DB에서 전 흐름: 김민우 개설(『함께 자라기』 함께 읽기, 정원 5·7일) → `/clubs` "모집 중" 카드 → 이서연 "참여하기" → 김민우 벨 `club_joined` "(2/5)" → 초대 모달에서 박지훈 → `club_invited` → 수락 → "모집 마감 → 시간 잡기" 활성 → confirm → 이서연 벨 `club_vote_request` → 상세에 투표 3슬롯 + **실제 리뷰(김민우·이서연)를 인용한 아젠다**(LLM 호출) → 게시판 글·댓글 → 관리자 목록 "시간 조율 중 · 3명" 사람 배지 → 모바일 390px 넘침 없음.

헤드리스 Chrome이 `stdio: 'ignore'`로는 이 세션에서 디버그 포트를 열지 못했다(파이프로 바꾸면 0.5초에 뜸) — 다음 시각 확인 스크립트는 파이프 + 실행마다 새 프로필 디렉터리 + `taskkill /T`.

## 운영 노트

- `club:deadlines`(00:00Z)가 이제 **모집 만료**까지 맡고 관리자 "기한 작업 지금 실행"에 "모집 만료 N"이 찍힌다. 모집 만료 → 조율 진입은 아젠다 생성(LLM)을 포함하므로 키가 없으면 일반 질문으로 폴백.
- 마이그레이션: `clubs` ALTER 6개 + `club_posts` — 추가만, 백필 없음. 기존 운영 행은 전부 `origin='agent'`.
- 매처의 busy·cooled·책 쿨다운은 origin을 가리지 않는다 — 사람 모임 참가자는 그동안 에이전트 초대를 받지 않고, 방금 사람들이 모인 책은 3개월간 에이전트가 다시 제안하지 않는다(테스트로 고정).
- 모집 중 사람 모임의 상세(제목·소개·참가자·완독 배지)는 회사 전체에 보인다 — 의도한 공개 모집. 게시판은 여전히 수락자만.
