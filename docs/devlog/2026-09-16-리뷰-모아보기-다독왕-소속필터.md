# 2026-09-16 리뷰 모아보기 — 다독왕 뱃지·필터와 소속별 보기

리뷰 모아보기는 "전체 리뷰가 추천순/최신순으로 쌓인 한 줄기"였다. 리뷰가 늘수록 남의 회사, 남의
부서 얘기가 섞여 들어오는데 걸러낼 방법이 없었고, 누가 쓴 글인지도 이름과 부서 텍스트뿐이라
"이 사람 말을 믿어도 되나"를 판단할 근거가 없었다.

## 한 일

- `reviewRepo.listAllWithMeta` — 두 번째 인자를 `sort` 문자열에서 옵션 객체로 바꿨다.
  `{ sort, company?, department?, team?, topReaderIds?, limit? }`. 소속 조건은 조건 배열로 모아
  `WHERE`를 조립하고, `topReaderIds`가 빈 배열이면 SQL을 타지 않고 바로 `[]`를 돌려준다.
- `reviewRepo.orgOptions()` 신설 — **리뷰를 실제로 남긴 사람**의 계열사/부서/팀 조합을 중복 없이.
- `rankingService.topReaders(limit)` 신설 — 개인·이달 스냅샷 상위 n명을 `{ userId, rank }`로.
  권수와 달성 시각이 모두 같을 때만 공동 순위(QA #93과 같은 규칙).
- `GET /api/reviews?scope=all` — `sort=rating`을 UI에 개방하고, `company`/`department`/`team`,
  `topReader=1`을 받는다. 응답은 `{ stats, reviews, orgs }`이고 각 리뷰에 `topReaderRank`가 붙는다.
- `shared/types` — `ReviewCard` / `ReviewOrg` / `ReviewFeed`. 페이지가 들고 있던 인라인 타입을 걷어냈다.
- `app/pages/reviews.vue` — 필터 줄(전체 · 우리 팀 · 우리 부서 · 우리 계열사 · 🏆 다독왕 리뷰)과
  `다른 조직 보기` 드롭다운, 정렬에 `별점순` 추가, 작성자 이름 옆 다독왕 뱃지, 0건일 때 필터 해제 안내.

## 설계에서 고른 것

- **다독왕 판정을 새로 짜지 않았다.** `rankingService`의 개인·이달 순위를 그대로 쓴다. 리뷰 페이지가
  따로 "반납 권수" SQL을 들고 있으면 랭킹 페이지와 뱃지가 언젠가 어긋난다. 30분 스냅샷 캐시(QA #56)도
  덤으로 공유해서, 같은 30분 안에서는 두 화면이 반드시 같은 사람을 다독왕이라고 부른다.
- **소속 필터는 상위 소속까지 AND로 묶는다.** "바텍/연구소"와 "레이언스/연구소"는 이름만 같은 다른
  조직이다. 랭킹의 `GROUP_CONFIG`가 이미 같은 이유로 상위 컬럼을 끼워 GROUP BY 하고 있어서, 필터도
  같은 규칙을 따랐다. 프런트의 소속 키(`바텍|연구소|플랫폼팀`)도 같은 이유로 상위 소속을 함께 담는다.
- **드롭다운 선택지는 리뷰 작성자에서 뽑는다.** 전체 사용자에서 뽑으면 고르자마자 "리뷰가 없어요"가
  뜨는 선택지가 섞인다. 고를 수 있는 건 결과가 있는 것뿐이어야 한다.
- **빠른 칩과 드롭다운이 같은 상태를 쓴다.** 둘 다 `orgKey` 하나를 읽고 쓰기 때문에, 드롭다운에서
  자기 팀을 골라도 "우리 팀" 칩에 불이 들어온다. 상태가 둘이면 반드시 어긋난다.
- **다독왕 색은 별점 토큰(`--star`/`--star-text`)을 재사용했다.** 금색을 하드코딩하면 다크 모드와
  색각 모드(`data-cvd`)에서 대비가 무너진다. VATECH 레드는 "나" 뱃지 같은 포인트 자리에만 남겼다.
- URL 쿼리 동기화는 뺐다. 필터 상태를 공유할 일이 아직 없다.
