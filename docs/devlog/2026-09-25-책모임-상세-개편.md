# 2026-09-25 책모임 상세 개편 — 후보 시간·즉시 확정·채팅

브랜치 `feat/club-detail`, 13커밋(구현 8 + 태스크 리뷰 수정 4 + 최종 리뷰 수정 1). 테스트 537 → 578건(게시판 5 삭제, 신규 46), 전부 통과. 빌드 통과.

## 왜

직접 개설을 써 본 민우: "사전 마감이 없네. 시간 잡기나 투표 기능도 없고. 채팅 기능도 없어." 사전 마감(모집 마감 → 시간 잡기)은 있었지만 3명 미만이면 비활성이고 이유를 안 보여줬고, 시간은 마감 *뒤에야* 시스템이 후보를 만들어 참여자가 "언제 만나는지" 모른 채 결정해야 했으며, 게시판은 모임 전 잡담에 무거웠다.

## 결정 (브레인스토밍)

개설자가 후보 시간을 미리 제안하고 참가자는 모집 중에 투표 / 사전 마감(시간 확정)은 개설자 마음대로(1명이어도) / 게시판을 SSE 실시간 채팅으로 교체 / 상세는 액션 줄 하나 + 2단(일정·참가자·토론 / 채팅).

## 무엇이 생겼나

- **후보 시간** — 개설 폼·상세에서 0~5개(날짜 + 30분 단위 시각, KST). 저장은 기존 `candidate_slots`. 고치면 표는 인덱스가 아니라 ISO로 다시 맞춘다(`remapVotes`).
- **모집 중 투표** — 사람 모임은 `inviting`에서도 `vote()`. 전원 투표 자동 확정은 없다(개설자가 닫는다).
- **시간 확정** — `POST /confirm { slot? }`: 개설자만, 인원 제한 없음, 기본은 최다 득표(동점·무표 → 가장 이른 미래 후보). `inviting → confirmed` 바로, 아젠다 생성, `club_confirmed`. 확인창에 득표 막대와 라디오. 후보가 없으면 기존 "모집 마감 → 시간 잡기"(시스템 후보 3개 → 조율)가 그대로.
- **기간 만료** — 후보 있으면 수락 2명↑ 자동 확정 / 개설자뿐이면 취소; 후보 없으면 기존 3명 규칙.
- **확정 뒤 참여** — 모임 KST 당일 전·정원 미만이면 참여·취소·초대·초대 수락이 열려 있다(`joinWindowOpen`·`hasSeat`). 새 참가자에겐 `club_confirmed` 즉시. 목록 "열려 있는 모임"에 "확정 · 자리 있어요"로 같이 보인다. `canViewClub`도 확정 사람 모임까지.
- **채팅** — `club_messages`/`club_message_reads`, 프로세스 내 pub/sub(`clubStream`), h3 `createEventStream` SSE(`?userId=&guestToken=`로 인증, 접속 즉시 ping, 25초 ping), `POST /messages`, 읽음, 안 읽은 수(카드 "새 메시지 n"), `club_chat` 알림은 모임당 KST 하루 1건(작성자·접속 중 제외), 시스템 메시지(참여·나감·후보 변경·확정). 게시판 코드 삭제(`club_posts` 테이블은 남음).
- **상세 페이지** — eyebrow `BOOK CLUB` + 상태 배지, 역할·상태별 액션 줄(왜 못 누르는지 한 줄), 일정 패널(후보 체크박스 + 득표 막대, 개설자 "후보 고치기" 인라인), 참가자 칩, 토론 질문, 오른쪽 sticky 채팅(≤900px 한 단).

## 운영 노트

- SSE 팬아웃은 프로세스 메모리 — Railway 컨테이너 1개 전제. 재배포 시 연결이 끊기고 `EventSource`가 스스로 재접속한다. 인스턴스가 늘면 브로커가 필요.
- `club:deadlines`의 모집 만료가 후보 있는 모임을 자동 확정한다(2명↑). 아젠다 생성(LLM) 포함.
- 마이그레이션: `club_messages`·`club_message_reads` 추가만. `club_posts`는 남는다(다음 정리 때 DROP).

## 장소 페이지 버튼 손질 (2026-09-25)

민우: "장소 페이지에 모임 버튼이 너무 크고 이상해. 모임 개설할 때만 보여야지." — 3단계 설계 §9는 "내가 호스트인 모임이 있으면 일반 장소 목록에도 노출"이었는데, 그러면 장소를 구경만 하려는 사람에게도 카드마다 빨간 블록 버튼(`『책』 모임 장소로`)이 붙는다.

- 버튼은 **모임 모드(`/places?forClub=`)에서, 그 모임의 개설자일 때만**. 일반 목록에서는 사라지고, 그 판정에 쓰던 `GET /api/clubs` 호출도 지웠다(장소 페이지 진입 시 요청 하나 감소).
- 디자인: 빨간 블록 → **레드 아웃라인 작은 버튼**(12.5px, 4px 10px, 호버 시 채움), 라벨은 책 제목 빼고 "이곳으로 정하기"(어느 모임인지는 위 띠가 말해준다). 카드 액션 줄(카카오맵 · 길찾기)의 첫 자리, 요약 카드도 동일.
- 헤드리스 확인: 일반 페이지 버튼 0개, `?forClub=1` 8개.

## 모임 만들기에서 장소도 미리 고르기 (2026-09-25)

민우: "모임 만들기에 왜 장소 고르기는 없어." 장소는 에이전트 모임 흐름을 물려받아 시간이 정해진 뒤(`scheduling|confirmed`)에만 정할 수 있었다. 바운디드로 판단해 설계는 채팅으로, 계획서 없이 바로 구현(브랜치 `feat/club-place-at-create`, 테스트 578 → 582).

- 서버: `setPlace`·`placeCandidates`가 사람 모임의 `inviting`을 허용(`placeStageOpen`). 장소 검증을 `normalizePlace`로 뽑아 개설과 확정이 같이 쓴다. `clubRecruitService.create`가 `place`를 받아 개설 직후 저장(알림 없음), 틀리면 400이라 모임도 안 생긴다. `POST /api/clubs`는 모양만 맞춰 넘긴다.
- 개설 폼: 후보 시간 아래 "장소 (선택)" — 책 검색과 같은 검색줄·결과 목록·선택 카드. 결과는 `/api/places`에서 카카오 id가 있는 곳만.
- 상세: 모집 중에도 개설자에게 `장소 고르기/바꾸기`. 장소 페이지 `?forClub=`의 호스트 판정도 모집 중을 받도록(처음 헤드리스에서 버튼 0개로 잡힘).
- 목록 카드: `시각 · 장소`.
- 헤드리스: 폼 장소 검색("광교 카페" 5건) → 선택 → 개설 → 상세 "모집 중 · D-8", 어디서 "써드하우스 (장소 확정)", 액션에 "장소 바꾸기" → 장소 페이지 모임 모드 버튼 8개, 누르면 상세로 돌아와 장소 교체 → 목록 카드 "써드하우스" → 비멤버는 장소는 보이고 버튼은 없음 → 모바일 넘침 없음. `shots-place/01~10`.
