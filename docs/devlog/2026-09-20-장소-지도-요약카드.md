# 2026-09-20 장소 페이지 — 핀을 누르면 지도 위에 요약 카드(네이버지도 방식)

모바일에서 지도 핀을 누르면 페이지가 맨 아래로 내려갔다. 지도를 다시 보려면 스크롤을 올려야 했다.

## 원인

핀 클릭 핸들러가 목록 카드에 `scrollIntoView`를 걸고 있었다. 이 메서드는 조건을 맞추려고
**스크롤 가능한 조상을 전부** 움직인다. 모바일(≤900px)은 지도 아래로 목록이 길게 이어지는
한 덩어리라(`.plist { overflow: visible }`), 창 자체가 목록 끝까지 따라 내려갔다.
PC도 마찬가지로 목록 패널만이 아니라 창까지 함께 움직일 수 있었다.

## 한 일 — 네이버지도식

핀을 누르면 **지도 위에 요약 카드**를 띄우고, 페이지는 움직이지 않는다.

- `app/components/reading/PlaceSummaryCard.vue` (신규) — 번호·이름·분류·거리·주소,
  동료 후기 태그 2개와 후기 수, 카카오맵·길찾기 링크, "목록에서 자세히 보기" 버튼.
  PC는 지도 좌측 하단, 모바일(≤640px)은 지도 아래쪽에 가로로 꽉 찬 시트처럼 붙는다.
- `app/pages/places.vue`
  - 지도와 카드를 `.map-stage`(relative)로 묶었다.
  - 핀 클릭: 카드만 띄운다. PC처럼 목록이 자체 스크롤 영역일 때만 **목록 안에서** 위치를 맞춘다.
  - "목록에서 자세히 보기"를 눌렀을 때만 페이지를 움직인다 — 스크롤 이동은 사용자가 요청할 때만.
  - 같은 핀 재클릭·Esc·× 로 닫힌다.
- `app/utils/scrollWithin.ts` (신규) — 컨테이너의 scrollTop만 직접 계산한다(창은 건드리지 않음).
- `app/utils/place.ts` (신규) — 목록과 카드가 함께 쓰는 `kakaoMapUrl`·`formatDistance`·`hasCoords`.
  기존에는 `places.vue` 안에만 있던 함수들이다.
- 테스트 14건 추가 (`scrollWithin` 5, `place` 헬퍼 7 … 전체 271건 통과)

## 검증 — 실제 앱 조작

개발 서버를 띄우고 헤드리스 Chrome을 CDP로 직접 몰아서(로그인 상태를 localStorage에 심고
카카오 지도 실핀을 클릭) 모바일 390×844, PC 1280×900에서 확인했다.

| 동작 | 모바일 | PC |
|---|---|---|
| 핀 클릭 | `window.scrollY` 0 유지, 카드 표시 | `scrollY` 0 유지, 카드 표시 |
| 목록 11번째 장소의 핀 클릭 | `scrollY` 0 유지 (지도 그대로) | 목록 내부만 스크롤(`scrollTop` 968), 창은 0 |
| "목록에서 자세히 보기" | 그때 페이지 이동(`scrollY` 1586), 해당 카드 화면 안 | 이미 보이므로 그대로 |

이전 UI 작업들과 달리 이번엔 브라우저에서 실제 클릭까지 확인했다.
