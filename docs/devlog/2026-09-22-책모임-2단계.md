## 무엇이 생겼나

조율중(scheduling) 모임의 "언제 만나는가"가 시스템 안에 잡힌다.

- **시간 후보 생성** (`server/utils/clubSlots.ts`, 순수 함수) — 다음 주 월~금 × 점심 12:00 / 저녁 18:30 KST. 참가자의 다른 확정 모임과 겹치면 제외, 아직 책을 든 사람의 반납 예정일 이후 제외, 사업장 2곳 이상이면 저녁 우선, **하루에 하나씩 먼저** 골라 3개. KST는 고정 +09:00(DST 없음)으로 계산하고 저장은 전부 ISO.
- **투표 → 확정** (`clubService`) — scheduling 진입 시 호스트 보장(리뷰 쓴 수락자 우선), 후보 3개, 투표 마감 = `min(진입일+2일의 23:59:59Z, 첫 슬롯−24h)`, `club_vote_request` 알림. 수락자만 투표(다중 선택), **전원이 투표하면 즉시 확정**, 아니면 마감 시 최다 득표(동점·무투표는 가장 이른 슬롯). 마감 처리 시점에 이미 지난 후보는 제외하고, 남은 미래 슬롯이 없으면 취소.
- **전날 리마인드·종료** — `club_reminder`는 24시간 창이 아니라 **KST 달력 날짜**로 "모임 전날 09:00 KST 실행"에 정확히 한 번. 모임 시각이 지나면 `done` + `done_at`(사람 쿨다운 "종료 후 4주"의 기준 — 1단계 이월 해결).
- **`.ics` 내보내기** — 외부 라이브러리 없이 한 이벤트짜리 iCalendar. `x-user-id` 헤더가 필요해 `<a href>`가 아니라 fetch → Blob으로 받는다.
- **독서 달력 일반화** — `ReadingCalendar`가 `loans` 전용에서 `events`로. 완독(표지) · **반납 예정(띠, 덤으로 생긴 기능)** · 모임(확정 실선 / 후보 점선 칩). 이벤트 조립은 순수 빌더(`app/utils/calendarEvents.ts`)로 빼서 테스트.
- **화면** — 상세에 시간 투표(득표 수·D-day), 확정 후 "내 캘린더에 추가 (.ics)"; 카드에 KST 시각; 관리자에 "기한 작업 지금 실행".
- **1단계 이월 정리** — `requireIdParam` 헬퍼로 `[id]` 파싱 통합, `expireInvites`의 도달 불가 분기와 그걸 검증한다던 테스트 삭제, `vitest.config.ts`에 `#shared` 별칭.

## 시각 확인

헤드리스 Chrome/CDP로 로컬 DB의 모임을 실제로 진행: 3명 수락 → 후보 3개(9/28·29·30 18:30, 회사 2곳이라 저녁 우선) → `club_vote_request` "9/24(목) 아침 9시에 마감" → 상세 투표 UI → 전원 투표 → 즉시 확정 9/29(화) 18:30 → `club_confirmed` → ics 200 (`DTSTART:20260929T093000Z`) → 내 서재 달력에 29일 칩 + 24일 반납 예정 띠 → 모바일 390px 넘침 없음.

첫 실행에서 표 하나가 유실된 것처럼 보였는데, 스크립트가 같은 틱에 `.click()`을 두 번 호출해 Vue가 첫 모델 갱신을 flush하기 전에 두 번째 change가 낡은 값을 읽은 것이었다(사람은 그렇게 못 누른다). 300ms 간격 재실험은 정상.

## 운영 노트

- `club:deadlines`(00:00Z = 09:00 KST)가 이제 **투표 마감·전날 리마인드·종료**까지 맡는다. croner는 놓친 실행을 따라잡지 않으므로, 실행을 놓치면 확정이 하루 늦어지고 **그 모임의 전날 리마인드는 영구히 빠진다**(날짜 창이 하루). 복구: 관리자 화면 "기한 작업 지금 실행".
- 컨테이너 `TZ`는 UTC여야 한다(Dockerfile 미설정 = UTC). `00:00Z ↔ 09:00 KST`와 마감의 `23:59:59Z` 관례가 여기 걸려 있다. 슬롯 생성·표시는 고정 오프셋이라 무관.
- 마이그레이션은 `ALTER TABLE clubs ADD COLUMN done_at TEXT`(PRAGMA 가드) 하나 — 추가만, 백필 없음.
- 브라우저가 KST가 아니면 달력 칸이 하루 어긋날 수 있다(라벨은 KST, 칸 매칭은 브라우저 로컬). 사내 도구라 허용.

## 3단계로 넘기는 것

- `slotDurationMinutes`가 KST 시(hour)로만 창을 판별 — `meet_at`이 창 밖 시각이 되면 길이를 잘못 추정. 3단계에서 장소 확정이 시각을 건드리지 않게 할 것.
- `.ics` 줄 접기(RFC 5545 §3.1, 75옥텟) 미구현 — Outlook/Google/Apple은 관대함. 접는다면 UTF-8 경계에서.
- `placeSuffix` 헬퍼(확정·리마인드 문구의 장소 접미사 중복) — `club_place_set`이 세 번째가 될 때.
- 확정과 전날 리마인드가 같은 실행에 연달아 도착할 수 있음(무해).
- 핸들러·태스크 수준 테스트 하네스가 없다 — 3단계의 host-only 장소 확정은 인가 버그가 데이터 버그가 되는 첫 엔드포인트라, 거기서 만든다.
- `requireIdParam` JSDoc의 호출처 개수(실제 6곳).
