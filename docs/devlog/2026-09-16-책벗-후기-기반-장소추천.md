# 2026-09-16 책벗 장소 추천에 사내 후기 근거 붙이기

어제 만든 장소 후기([[2026-09-16-장소-후기]])는 `/places` 화면에서만 보였다. 책벗에게 "근처 카페
추천해줘"라고 물으면 여전히 카카오 검색 결과(이름·거리)만 나열했다. 후기 데이터가 있는데 에이전트가
못 쓰고 있었다 — 그걸 이었다.

## 한 일

**핵심 발견**: 카카오 로컬 검색 결과의 `id`(`Place.kakaoId`)가 `place_reviews.kakao_place_id`와
같은 키다. 새 저장소도, 새 테이블도 필요 없고 join 한 번이면 된다.

- `placeReviewRepo.topPlaces({ tag?, limit })` — 장소별 집계. `tag`를 주면 그 태그가 하나라도
  달린 장소만 남기고 그 태그 수 많은 순, 없으면 총 후기 수 많은 순. 장소 이름은 **가장 최근 후기**의
  것을 쓴다(사람마다 이름을 조금씩 다르게 적을 수 있어서). `summaryByIds`와 같은 이유로 SQL 집계
  대신 전부 읽어 JS에서 센다.
- `shared/types`에 `ReviewedPlace` — 카카오 검색 없이 후기만으로 만든 장소 집계(좌표·거리 없음).
- `server/ai/tools/placeReviewDigest.ts` — 순수 변환 모듈. `toAgentPlaces`(카카오 결과 + 후기 요약),
  `toAgentReviewedPlaces`(후기 집계). 태그는 코드(`quiet`)가 아니라 **라벨**(`조용해요`)로 바꿔서
  모델에 넘긴다. 코멘트는 `김민우(개발팀): 창가 자리 좋아요` 형태로 사람과 부서를 붙였다.
- `search_reading_places` 개선 — `userId`를 받고, 검색 결과의 `kakaoId`를 모아 `summaryByIds`를
  **한 번** 호출해 각 장소에 `reviews: { total, tags, comments }`를 붙인다. LLM 라운드트립 추가 없음.
- `search_reviewed_places` 신설 — 카카오를 거치지 않고 `place_reviews`만 보는 도구. "동료들이
  조용하다고 한 곳"처럼 거리보다 평가가 중요한 질문을 맡는다. `tag`는 선택.
- `defaults.ts`의 chat 프롬프트에 두 도구를 나눠 쓰는 규칙 추가.
- `agent.ts`의 `toolDetail`에 두 도구를 추가 — 스트리밍 중 활동 줄에 `카페`, `조용해요`가 뜬다.

## 설계에서 고른 것

- **후기 0건이면 `reviews` 키를 아예 만들지 않는다.** `total: 0`을 보내면 모델이 "후기가 없지만
  좋아 보여요" 같은 말을 지어내기 쉽다. 키가 없으면 도구 설명("reviews 없는 장소엔 후기를 지어내지
  말라")과 맞물려 더 단단하다. 토큰도 아낀다.
- **요약은 배열 순서가 아니라 `kakaoId`로 맞춰 붙인다.** 폴백 예시 장소처럼 `kakaoId`가 없는
  경우가 있어서, 인덱스로 짝지으면 엉뚱한 장소에 남의 후기가 붙는다.
- **도구를 하나로 합치지 않았다.** `search_reading_places`는 거리가 축, `search_reviewed_places`는
  후기가 축이다. 한 도구에 `sort` 파라미터를 두는 것보다 이름으로 갈라 두는 편이 모델이 덜 헷갈린다.
- 후기 데이터가 아직 얇아서 `search_reviewed_places`가 빈 결과를 낼 수 있다 → 빈 배열 대신
  "`search_reading_places`로 넘어가라"는 `message`를 돌려준다.

## 검증

TDD로 진행 — 세 묶음 모두 빨간 것을 먼저 확인하고 구현했다.

- `tests/placeReviewTopPlaces.test.ts` (5) — 빈 DB, 장소별 묶기·정렬, 태그 필터(태그 없는 장소 제외),
  limit, 최근 후기 기준 이름·코멘트.
- `tests/placeReviewDigest.test.ts` (6) — 라벨 변환·정렬, 후기 0건에 `reviews` 없음, `kakaoId` 없는
  장소, 순서가 어긋난 요약 매칭, 거리 없음 → `null`.
- `tests/placeReviewTools.test.ts` (4) — 카카오 fetch를 stub하고 도구를 실제로 `invoke`해 후기가
  붙는지, 키 없을 때 호출조차 안 하는지, 후기 없을 때 안내 메시지가 나오는지.
- 전체 `npm test` — 30 파일 153개 통과.

## 남은 것

- **운영 DB의 `ai_settings`는 그대로다.** `defaults.ts`는 시딩·"기본값 복원"의 원본일 뿐이라,
  이미 시딩된 운영 프롬프트에는 새 규칙이 없다. 관리자 화면에서 기본값 복원을 누르거나 해당
  문단을 직접 붙여야 한다(도구 설명 자체에 안내가 들어 있어 없어도 동작은 한다).
- 시연 전에 `npm run seed:demo`로 후기를 몇 건 심어야 `search_reviewed_places`가 살아난다.
