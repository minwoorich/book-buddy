## 후속 3 — 책벗 답변에 버튼이 빠지는 문제 (민우 보고)

- **증상**: "리뷰 작성 페이지로 이동해드릴게요. 아래 버튼을 눌러주세요!"인데 버튼이 없음.
- **재현·원인**: 실제 에이전트로 대출 → "네, 진행해줘" → "리뷰 달고 싶어"를 돌리자 3번째 턴에서 모델이 JSON 없이 평문으로 답했다(actions 자체가 없음). 1·2턴은 정상 JSON. 원인은 히스토리 형식 — 클라이언트가 이전 assistant 턴을 평문 message만으로 되돌려 보내니 모델이 그 형식을 따라가 JSON을 버림. 라이브 ai_settings는 코드 기본값과 동일해 프롬프트 차이는 아님.
- **수정(원인 + 다층 방어)**
  1. `app/utils/chatHistory.ts` — assistant 턴을 모델이 냈던 `{"message","bookIds","actions"}` JSON으로 되돌려 보냄(형식 일관성). 서버는 여기서 최근 책 id도 읽는다.
  2. 프롬프트 — "후속 턴에서도 예외 없이 JSON", "버튼을 언급했으면 반드시 actions에 포함" 규칙 추가. 경로 카탈로그에 `/reviews`·`/notices`·`/` 추가.
  3. `server/ai/enrich.ts` — 결정적 보정: 확인 질문→네/아니오, 분야 질문→카테고리 칩 4개, 본문 키워드→내 서재/캘린더/랭킹/피드/장소/공지/리뷰 모아보기, "리뷰 작성"+문맥 책→리뷰 쓰기, "상세"→책 상세, 버튼을 약속했는데 목적지가 없으면 문맥 책 상세. 같은 목적지 중복 금지, navigate 최대 3개. runAgent·streamAgent 모두 적용.
  4. `parse.ts` — 화이트리스트를 실제 라우트 전부로 넓히고, `/books/12/review`·`?review=true`·`/book/12`·끝 슬래시를 정규화(걸러서 버튼을 잃지 않게).
  5. AiSearchPanel — 단발 검색에선 reply 버튼을 숨기고 navigate만 처리(예전엔 reply가 오면 `navigateTo(undefined)`).
- 테스트: enrichAnswer 12건, chatHistory 1건, 경로 정규화 10건 → vitest 83/83.
