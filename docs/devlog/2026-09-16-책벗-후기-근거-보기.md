# 2026-09-16 책벗 장소 추천에 "후기 근거 보기" 버튼

[[2026-09-16-책벗-후기-기반-장소추천]]으로 책벗은 동료 후기를 **읽고** 추천하게 됐다. 그런데 사용자에게
보이는 건 여전히 문장 한 줄이다 — "동료 3명이 조용하다고 했어요." 그 3명이 누구고 뭐라고 썼는지는
도구 결과 안에만 있고 화면에는 끝내 안 나온다. 말한 근거를 **확인할 수 있게** 만드는 작업.

## 한 일

- `shared/types`에 `PlaceEvidence { name, total, tags, comments, mapUrl }` — 채팅에 동봉되는 근거 한 덩어리.
- `server/ai/placeEvidence.ts` 신설(순수 모듈) — `collectPlaceEvidence(messages, answerText)`.
  에이전트 실행 결과의 ToolMessage 중 `search_reading_places` / `search_reviewed_places` 것만 골라
  JSON을 파싱하고, **답변 본문에 이름이 실제로 나온 장소만** 남긴다.
- `runAgent`가 `{ answer, usage, places }`를 돌려주고, `/api/ai/chat`이 `places`를 함께 응답한다.
- `useChat`의 `ChatMsg`에 `places?`. sessionStorage에 같이 저장되니 새로고침해도 근거가 남는다.
- `ChatMessage.vue`에 토글 액션 버튼(`후기 근거 보기 · 2곳`)과 펼침 패널. 패널은 장소마다
  이름·총 후기 수, 태그 집계 칩, `"창가 자리가 넓어요" — 김민우 · 개발팀` 인용, 지도 링크를 보여준다.
  칩·인용 스타일은 `/places`의 `PlaceReviewPanel`과 같은 언어로 맞췄다 — 같은 데이터니 같아 보여야 한다.

## 설계에서 고른 것

- **모델에게 근거 버튼을 만들라고 시키지 않았다.** 액션 JSON에 장소 id를 실어 달라고 하면 없는 후기를
  지어내거나 id를 흘릴 여지가 생긴다. 서버가 도구 결과에서 직접 뽑으면 화면에 뜨는 근거는 **반드시 실재한다**.
  `enrich.ts`가 빠진 버튼을 서버에서 결정적으로 채우는 것과 같은 결.
- **`kakaoId`를 새로 뚫지 않았다.** digest가 이미 `name/total/tags/comments/mapUrl`을 다 담고 있어서
  추가 API 호출도, 도구 출력 변경도 필요 없었다.
- **언급 판정에 후기 없는 장소 이름까지 포함한다.** 처음엔 근거 있는 장소만 이름 대조하고, 하나도 안
  걸리면 후기 많은 순 3곳으로 폴백하게 짰다. 그러자 "스타벅스(후기 0건)가 가까워요"라고 답한 턴에서
  폴백이 끼어들어 **추천하지도 않은 커피베이의 후기**를 근거랍시고 보여줬다. 테스트가 먼저 잡았다.
  지금은 후보 중 어느 이름이라도 불렸으면 폴백을 끄고, 아무 이름도 안 불렸을 때만(모델이 이름을 줄여
  쓰거나 뭉뚱그린 경우) 상위 3곳으로 돈다.
- **`streamAgent`는 건드리지 않았다.** 검색 패널은 책이 주제고, 장소 추천은 채팅에서만 일어난다.
