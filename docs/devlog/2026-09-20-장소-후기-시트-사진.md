# 2026-09-20 장소 후기 — 시트로 모으고 사진 후기 추가

"장소 페이지에서 후기 보는 게 불편하다"에서 시작했다. 코드를 보니 불편의 정체가 셋이었다.

- **후기를 다 볼 방법이 아예 없었다.** `placeReviewRepo`의 `RECENT_MAX = 2` — 후기가 10건이어도
  코멘트는 영원히 2건만 보인다. 태그도 상위 3개만 나와서 부정 태그(`시끄러워요`)가 묻힐 수 있었다.
- **카드가 길었다.** 목록 카드마다 집계 칩 + 코멘트 2줄 + 작성 폼이 통째로 붙어 있어,
  PC 목록(560px 스크롤 칸)에 두세 장밖에 안 들어갔다.
- **모바일은 페이지가 끝없이 늘어났다.** 지도 300px 아래로 그 긴 카드가 그대로 쌓인다.
  [[2026-09-20-장소-지도-요약카드]]에서 지도 요약 카드를 만들었지만, "목록에서 자세히 보기"를
  누르면 결국 페이지가 아래로 밀려 지도가 화면에서 사라졌다.

## 한 일

**후기 시트** (`app/components/reading/PlaceReviewSheet.vue`, 신규) — PC는 가운데 모달,
모바일(≤640px)은 바텀시트. `ReaderProfileModal`의 세로 배치 규칙을 그대로 따랐다
(머리·탭은 `flex: none`, 본문만 `flex: 1; min-height: 0`으로 남는 높이를 받아 스크롤).
목록 카드와 지도 요약 카드 **양쪽에서 같은 시트를 연다.**

**탭 둘 — 전체 후기 / 사진 후기.** "사진만 모아보고 싶다"는 요구를 저장 구조가 아니라 보기
방식으로 풀었다. 사진은 후기에 딸린 채로 두고(주인이 분명하고, 1인 1후기라 스팸이 안 쌓이고,
후기를 지우면 사진도 같이 정리된다) 사진 탭에서만 그리드(PC 3열·모바일 2열)로 크게 깐다.
업로드 경로를 따로 열면 주인 없는 사진·삭제 권한·신고 처리·테이블이 늘어나는데, 얻는 건
"후기 없이 사진만 올리기"뿐이라 남는 장사가 아니다. 탭 전환은 `GET /api/place-reviews/{id}`
응답 하나로 클라이언트에서만 거른다 — 추가 요청 없음.

**사진 업로드** — 이미 있는 파이프라인(`uploadService`, 커뮤니티 글쓰기·QA 피드백과 같은
multipart 방식)을 그대로 썼다. 후기당 최대 3장.

- `place_reviews.image_paths TEXT NOT NULL DEFAULT '[]'` — `qa_feedback.image_paths`와 같은
  ALTER TABLE 방식이라 운영 DB도 그대로 살아난다.
- `PUT /api/place-reviews/{id}`를 JSON body → multipart로 전환. 쓰는 곳이 한 곳뿐이라 안전했다.
  수정은 `keepImages`(남길 기존 경로) + `image`(새 파일)로 목록을 다시 만들고, 빠진 파일은
  `uploadService.remove`로 지운다. **클라이언트가 보낸 keep 경로는 실제로 내 후기에 달려 있던
  것만 인정한다** — 남의 사진 경로를 끼워 넣어 내 후기에 붙이는 걸 막는다.
- 파일을 디스크에 쓰기 **전에** 나머지 필드를 검증한다. 태그가 비어 400이 나는데 사진만 저장돼
  주인 없는 파일이 남는 걸 막으려고.
- 삭제할 때 사진 파일도 같이 지운다(`removeMine`이 지운 후기의 경로를 돌려준다).

**카드는 한 줄 신호로 축소** — `PlaceReviewPanel`에서 폼과 코멘트 목록을 걷어내고 태그 집계 3개 +
사진 썸네일(+N) + 최근 한 줄(말줄임) + `후기 N ›`만 남겼다. 최근 한 줄을 `nowrap + ellipsis`로
자르는 게 카드 높이를 고정하는 핵심이라 테스트로 못 박아 뒀다.

**Esc 두 겹** — 라이트박스가 떠 있으면 Esc는 라이트박스만 닫고, 지도 요약 카드까지 같이 닫히지
않게 `places.vue`의 핸들러도 시트 여부를 본다. 한 번의 Esc로 두 겹이 사라지면 안 된다.

## 2차 — "디자인이 너무 AI 티가 난다"

화면을 받아보고 나온 지적이 셋. 태그가 글자 중간에서 깨지고("채…"), 카드 레이아웃이 어수선하고,
시트가 AI가 찍어낸 것처럼 보인다.

**원인은 이 앱의 톤을 안 따른 것이었다.** 이 프로젝트는 "에디토리얼 서재"고, 같은 종류의 화면인
책 리뷰 목록(`components/review/ReviewList.vue`)은 **카드 채움 없이 구분선 한 줄, 반경 3px,
액션은 밑줄 텍스트**로 되어 있다. 알약이 하나도 없다. 그런데 내가 만든 후기 영역은 알약(999px)
집계 칩 + 분홍 채움 카드 + 빨간 배지 + 빨간 테두리 알약 버튼 + 사진 위 그라데이션 덮개를
한 화면에 다 넣었다. 요소마다 모양이 다르고 강조가 고르게 퍼져 있으니, 위계 없이 알록달록한
"생성된 UI" 느낌이 난다.

태그 깨짐도 같은 뿌리다. 칩을 `nowrap`으로 늘어놓고 줄을 `overflow: hidden`으로 잘랐으니
넘치는 지점이 낱말 경계가 아니라 칩 한가운데였다.

### 바꾼 것

- **집계는 칩이 아니라 한 줄 문장.** `콘센트 있어요 3 · 자리 넓어요 2 · 채광 좋아요 1`.
  줄 전체를 `nowrap + ellipsis`로 자르니 넘침이 말줄임으로 정리된다 — 깨질 자리가 없다.
- **후기 줄을 ReviewList 규칙으로.** 분홍 채움·빨간 배지 제거. 내 후기는 이름 옆 작은 빨간
  글자 "내 후기"로만 표시하고, **수정·삭제를 그 줄에 밑줄 텍스트(`mini-act`)로** 뒀다.
  본문(14.5px/1.6)이 주인공이고 태그는 그 아래 작은 회색 글자.
- **탭 줄에서 빨간 알약 버튼을 뺐다.** 내 후기가 있으면 수정은 그 후기 줄에 있으니, 탭 줄에는
  후기가 없을 때만 `후기 남기기`(`.btn sm`, 반경 3px)를 둔다.
- **사진 그리드의 그라데이션 덮개 제거** — 설명을 사진 아래 작은 글씨로 내렸다.
- **장소 카드 윗줄 재배치**: 번호+이름+거리 한 줄, 카테고리는 주소와 합쳐 아랫줄로.
  이름이 길 때 카테고리가 옆에서 눌려 "매머드익스프레 스"로 깨지던 게 사라지고 줄도 하나 줄었다.
  시트 머리말도 같은 규칙으로 맞췄다.
- 지도 요약 카드의 `목록에서 자세히 보기`도 알약 → 옆 링크들과 같은 밑줄 텍스트로.

### 가드

`tests/placeReviewSheet.test.ts`에 **"에디토리얼 톤 유지"** 가 추가됐다 — 세 컴포넌트의 스코프드
스타일에 `border-radius: 999px`, `linear-gradient`, `background: var(--red-tint)`가 다시
들어오면 실패한다. 집계·코멘트 줄의 말줄임 가드도 묶인 규칙(`.tally, .say`)까지 보도록 고쳤다.
(지도 핀 번호 배지의 `--red` 바탕은 핀과 짝을 맞추는 것이라 예외.)

## 3차 — 태그 배지

2차에서 태그를 한 줄 텍스트로 바꿨더니 이번엔 **태그 경계가 안 보였다.**
`콘센트 있어요 · 자리 넓어요`가 한 덩어리로 읽힌다. 가운뎃점만으로는 약했다.

전역 `.tag-badge`(main.css) 하나를 두고 세 군데(목록 카드·지도 요약 카드·시트)에서 쓴다.
**이모지 + 연한 빨강(`--red-tint`) 바탕 + 반경 3px 직사각형** — 알약(999px)이 아니다.

- 이모지는 `PLACE_TAGS`에 `emoji` 필드로 넣었다. `label`에 섞지 않은 이유는 라벨이
  AI 프롬프트(`searchReviewedPlaces`)와 후기 다이제스트(`placeReviewDigest`), `agent.ts`의
  근거 문구에도 그대로 쓰이기 때문이다. 이모지가 프롬프트에 섞여 들어갈 일이 없다.
  🤫 조용 · 🔌 콘센트 · 🪑 자리 · ⏳ 오래 · ☀️ 채광 · 🔊 시끄러움
- **배지가 스스로 줄어든다.** `min-width: 0` + 배지 안쪽 말줄임. 1차에서 태그가 "채…"로
  깨졌던 건 컨테이너가 칩 한가운데를 잘랐기 때문인데, 이제 좁아지면 배지가 제 글자를 줄인다.
  목록 카드의 태그 줄은 `flex-wrap: nowrap`이라 태그가 늘어도 카드가 두 줄로 커지지 않는다.
- 라이트박스는 어두운 바탕이라 연한 빨강이 안 보인다 — 거기서만 반투명 흰색으로 바꿔 끼운다.

톤 가드는 그대로 두되(알약·그라데이션·스코프 안 분홍 채움 금지), 배지 바탕은 전역에 한 번만
있다는 점을 주석으로 못 박았다. 컴포넌트마다 다시 칠하기 시작하면 그때부터 알록달록해진다.

## 4차 — 배지 줄마다 빈 띠가 생기던 버그

시트를 열면 집계 배지 줄과 후기 줄 태그 주위로 세로 빈 공간이 크게 생기고, 태그가 왼쪽으로
밀려 있었다. 후기 줄에서는 `수정·삭제`가 태그와 같은 줄이어야 하는데 아래로 내려갔다.

**원인: 클래스 이름 충돌.** 배지 컨테이너에 여러 줄 허용 수식으로 `.tag-badges.wrap`을 붙였는데,
`.wrap`은 이 앱의 **페이지 바깥 틀**이다 — `main.css`의 `.wrap { max-width: 1100px;
margin: 0 auto; padding: 40px 24px 90px; }`. 배지 줄마다 위 40px·아래 90px 여백과 왼쪽 24px
들여쓰기가 그대로 먹혔다. 화면에서 잰 간격이 정확히 그 값이었다.

`display: flex`인 컨테이너가 왜 세로로 벌어지는지 CSS만 읽어선 설명이 안 됐는데, 스코프드 스타일
바깥의 전역 규칙을 찾아보고서야 잡혔다. **제네릭한 유틸 이름을 수식 클래스로 쓰면 안 된다** —
Vue 스코프드 스타일은 전역 클래스를 막아주지 않는다.

- `.tag-badges`는 이제 **기본이 여러 줄**이고, 한 줄에 가둬야 하는 곳(목록 카드·지도 요약 카드)만
  스코프에서 `flex-wrap: nowrap; overflow: hidden`으로 덮는다. 수식 클래스가 사라졌다.
- 가드 추가: 세 컴포넌트의 어떤 요소도 `wrap` 클래스를 달 수 없다.

## 후기 남기기 버튼

테두리 상자(`.btn sm`)를 버리고 시트 안의 다른 액션(수정·삭제, 카카오맵 링크)과 같은 **글자
버튼**(`+ 후기 남기기`, 빨강, 호버 밑줄)으로 바꿨다. 상자로 두면 **간편 모드**에서
`html[data-simple="true"] .btn { min-height: 44px; font-size: 15px; border-width: 2px }`가
걸려 탭 줄 안에서 혼자 부풀어 오른다. 빈 목록의 "첫 후기를 남겨보세요"도 눌러서 바로 열리게 했다.
