# 2026-09-15 책벗(AI) 장애 — 키 폐기 + 401 오인 로그아웃

## 증상

- 라이브(vnlibrary.com)·로컬 모두 책벗에 질문하면 "로그인 정보가 만료됐어요" 알림 후 로그아웃.
- 콘솔: `POST /api/ai/chat` 401. Railway 로그: Anthropic `authentication_error: API key is invalid`.

## 원인 (둘이 겹침)

1. **Anthropic API 키 폐기** — 커밋 976097b에서 실수로 `.env.example`에 실제 키가 들어간 채 공개 저장소에
   푸시됨. ec5b452에서 파일은 비웠지만 이미 노출된 키를 Anthropic이 자동 폐기. 로컬 `.env`와 Railway 변수가
   전부 이 키라 양쪽 다 실패.
2. **업스트림 401이 우리 인증 401로 새는 버그** — `handleApi`는 `ApiError`만 변환하고 나머지는 그대로 던졌는데,
   Anthropic SDK 에러는 `status: 401` 필드를 갖고 있어 h3가 그 코드를 그대로 HTTP 응답 코드로 사용. 클라이언트
   `useApi`의 "로그인 상태에서 401 = 유령 세션" 처리가 발동해 로그아웃시킴.

## 처리

- `server/utils/errors.ts`에 `toHttpError()` 추가: ApiError는 그대로, `status`/`statusCode`를 가진 외부 SDK 에러는
  **502 + 일반 문구**("AI 서비스 응답에 문제가 있어요…")로 감싼다. `handleApi`와 `search-stream`의 사전 검증
  catch에 적용. 진짜 인증 401(로그인 안 됨)은 그대로 401.
- 테스트 `tests/toHttpError.test.ts` 4건 추가 (vitest 43/43).
- 로컬 재현 확인: 폐기된 키 상태에서 `/api/ai/chat`·`/api/ai/places` → 502, 비로그인 → 401 유지.

## 남은 일 (민우)

- console.anthropic.com에서 새 키 발급 → 로컬 `.env` + Railway `NUXT_ANTHROPIC_API_KEY` 교체. 키는 절대 커밋 금지.
- 이 수정 커밋·푸시 → Railway 재배포.
