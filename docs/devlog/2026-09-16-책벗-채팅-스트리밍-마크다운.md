# 2026-09-16 책벗 채팅 스트리밍 + 마크다운 렌더링

책벗에게 물어보면 답이 다 만들어질 때까지 로더만 돌았다. 도구를 네댓 번 부르는 질문은 30초를
넘기는데 그동안 화면에는 "책벗이 서가를 걷는 중..."만 있었다. AI 검색(`/api/ai/search-stream`)은
이미 스트리밍인데 정작 대화가 아니었다. 게다가 도착한 답변은 `**클린 코드**`, `1.` 목록 기호가
그대로 보여서, 모델이 애써 구조를 잡아 쓴 게 오히려 읽기 나빠졌다.

## 한 일

### 스트리밍

- `server/api/ai/chat-stream.post.ts` 신설 — `search-stream`과 같은 골격의 SSE 엔드포인트.
  로그인·메시지·설정·키 검증은 스트림을 열기 **전에** 끝낸다(한 번 SSE가 시작되면 상태 코드를
  바꿀 수 없다 — 401/400/503은 평범한 JSON 에러로 나가야 클라이언트 폴백이 동작한다).
  진행 중 `tool`/`delta`를 중계하고, 끝나면 `done`에 answer·books·places·recommend를 한 번에 싣는다.
- `streamAgent` — 지금까지 검색 전용이라 장소를 몰랐다. `placeCollector`를 도구에 주고
  `on_tool_end`마다 도구 메시지를 쌓아, `runAgent`와 **같은 재료**로 근거(`collectPlaceEvidence`)와
  추천(`pickRecommendation` → `withPlaceAction`)을 계산하도록 맞췄다.
- `toolMessageFromStreamEvent` (`placeEvidence.ts`) — 비스트리밍은 끝난 뒤 `res.messages`를 읽지만
  스트리밍엔 그 목록이 없다. `on_tool_end`의 output(ToolMessage)에서 같은 모양을 만든다.
- `app/utils/sse.ts` 신설 — `createSseParser`(프레임 상태기계) + `readSseStream`. 검색 패널이 인라인으로
  갖고 있던 파싱을 꺼내 채팅과 공유한다. `app/utils/aiTools.ts`로 도구 한국어 라벨도 공용화.
- `useChat.send()` — `$fetch`는 스트리밍 바디를 못 읽으므로 raw `fetch`. `streamText`/`activity` 상태를
  새로 노출하고, `done`이 오면 완성 메시지를 push한다.
- `ChatWidget` — 첫 글자 전에는 로더(무슨 도구를 쓰는 중인지 라벨), 델타가 오기 시작하면 타자기
  말풍선(캐럿 깜빡임, `prefers-reduced-motion` 존중). `done`에서 책·액션·근거가 붙은 말풍선으로 교체.

### 마크다운

## 설계에서 고른 것

- **마크다운 라이브러리(marked+DOMPurify)를 안 넣었다.** 원문을 통째로 이스케이프한 뒤 우리가 아는
  문법만 태그로 되돌리는 "이스케이프 우선" 방식이라, 모델이 HTML을 흘리거나 사용자 입력을 그대로
  인용해도 태그가 살아날 틈이 없다. 링크는 `http(s)`·앱 내부 경로만 허용하고 나머지 스킴은 링크로
  만들지 않는다(`javascript:` 등). 지원 범위도 말풍선에 필요한 만큼으로 좁혔다.
- **스트림이 열린 뒤에는 절대 폴백하지 않는다.** `fetch` 자체가 실패한 경우(=에이전트가 아직 돌지
  않음)에만 기존 `/api/ai/chat`으로 재시도한다. 읽는 도중 끊겼을 때 재시도하면 이미 실행된
  대출·예약 도구가 한 번 더 돌 수 있다. 중간에 끊기면 그때까지 받은 텍스트로 마무리한다.
- **최종 신뢰 소스는 여전히 "누적 텍스트를 parseAiAnswer로 파싱한 결과"다.** 델타는 보여주기 전용이고,
  책·버튼·근거는 끝난 뒤 서버가 도구 결과로 결정한다(모델이 아니라).

## 구현 중 발견한 것 (고침)

`curl`로 SSE를 확인하는데 `delta`가 하나도 안 나왔다. 처음엔 추출기 버그를 의심했지만, 직접
`streamAgent`를 호출해 보니 델타가 64개 정상으로 나왔다. 차이는 **curl 인자의 한글이 깨져** 모델이
"메시지가 깨져서 확인이 어려웠어요"라고 평문으로 되물은 것이었다(UTF-8 파일로 보내니 델타 35개 정상).

그런데 그 우연이 진짜 구멍을 드러냈다: **모델이 JSON 대신 평문으로 답하는 턴에서는 델타가 0개**다.
`createMessageExtractor`가 `"message"` 키를 찾는 상태기계라서, 키가 없으면 아무것도 못 흘린다.
평문 응답은 드물지 않다(그래서 `enrich.ts`가 있다). `{`를 한 번도 못 본 채 60자가 쌓이면 "이 턴은
평문"으로 보고 원문을 그대로 흘리는 폴백을 넣었다. 임계치는 `물론이죠, ...\n```json\n{`처럼 서론이
붙은 경우를 평문으로 오해하지 않을 만큼 넉넉하게 잡았다(테스트 4·7이 그 경계를 지킨다).
