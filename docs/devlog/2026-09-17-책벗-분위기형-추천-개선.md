# 2026-09-17 책벗 — "퇴근길에 가볍게 읽을 에세이" 추천 개선

"퇴근길에 가볍게 읽을 에세이 추천해줘"라고 물으면 책벗이 제대로 답하지 못했다.

## 재현 (운영 컨테이너, 조회 도구만)

- `search_books`를 15~19회 호출했다: 에세이 → 산문 → 문학 → 여행 → 김영하 → 고양이 …
  입력 토큰 약 9.8만, 응답까지 35초.
- 한 번은 최종 답변이 "세 권 중 원하시는 걸로 대출해드릴까요?"뿐이고 책 목록과 `bookIds`가 비어 있었다.
  모델이 도구 호출과 **같은 턴에** 추천 본문을 써 버렸고, 스트리밍은 마지막 턴 텍스트만 답으로 쓰기 때문에
  그 본문이 버려졌다.

## 원인

- 운영 서가 780권의 카테고리는 **자기계발·인문·경제경영·IT · 프로그래밍** 4개뿐이다. 에세이·소설 같은 장르 분류가 없다.
- `search_books`는 제목·저자만 검색했고, 카테고리는 정확히 일치해야 했다. 모델은 카테고리 목록을 몰랐다.
  그래서 "에세이"로 찾으면 항상 `[]`가 나왔고, 모델은 멈출 근거가 없어 키워드만 바꿔 가며 계속 검색했다.
- 운영 DB의 chat 프롬프트는 코드 기본값에서 9/16 "장소 후기 근거" 규칙 한 줄이 빠진 상태였다.
  프롬프트는 `ai_settings`가 원본이라 코드만 배포해서는 반영되지 않는다.

## 한 일

- `bookRepo.findAll({ inDescription })`: 책벗 검색에서는 소개글까지 찾는다. 제목·저자 적중은 2점,
  소개글 적중은 1점으로 매겨 정렬한다. 홈 검색은 기존대로 제목·저자만 본다.
- `search_books`
  - 결과를 `{ books, note? }` 형태로 돌려주고, 책마다 소개 요약(`summary`, 80자)을 붙였다.
  - 도구 설명에 실제 카테고리 목록을 넣었다(요청마다 DB에서 읽음).
  - 없는 카테고리를 넣었거나 결과가 비었으면, 빈 배열 대신 `note`로 알려 준다:
    "장르 분류는 없다 → 한두 번만 더 찾고 멈춰라 → 가장 가까운 책을 제안하고 `search_external_books`로 희망도서를 안내하라".
- 프롬프트(`CHAT_SYSTEM_PROMPT`)
  - 상황·분위기형 추천 규칙을 추가했다: 분위기 단어를 한 번에 넣어 1~2회만 검색하고, 가까운 사내 도서 2~3권과
    외부 에세이·희망도서 신청을 함께 제안한다.
  - "도구를 호출하는 중간 턴에는 답변을 쓰지 않는다" 규칙을 추가했다.
- `tests/searchBooksTool.test.ts` 6건 추가 (전체 263건 통과)

## 검증 (운영 도서 780권 + 운영 프롬프트, 로컬 실행)

| | 도구 호출 | 입력 토큰 | 시간 | 책 카드·버튼 |
|---|---|---|---|---|
| 수정 전 (운영) | 15~19회 | 9.7~9.8만 | 35~37초 | 없음 / 본문 유실 |
| 도구만 수정 | 11회 | 8.5만 | 35초 | 없음 (평문 답변) |
| 도구+프롬프트 수정 | 4~6회 | 4.9~5.8만 | 23~25초 | 있음, 외부 에세이 희망도서 제안까지 |

도구 수정만으로도 추천 내용은 좋아졌다. 하지만 호출 횟수와 JSON 형식은 프롬프트까지 바뀌어야 잡혔다.
그래서 배포 후 운영 `ai_settings`의 chat·search 프롬프트를 기본값으로 복원한다.
운영 DB 프롬프트에 관리자가 수정한 내용이 없다는 것은 코드 기본값과 diff로 확인했다.
