# 2026-09-13 초기 설계 의사결정

브레인스토밍 세션에서 민우가 내린 결정들. 설계서: [[../superpowers/specs/2026-09-13-book-buddy-design|Book Buddy 설계서]]

## 프로젝트 성격

- **1일짜리 데모 프로젝트** — 실제 사내 시스템에 배포하지 않는다
- 따라서 **보안·재고 정합성은 느슨하게** (엄격한 인증, 다중 재고 관리 불필요)

## 기능 범위

- 4개 AI 기능 **모두 포함, 동시에** 진행 (단계별 MVP 대신): 추천 · 검색/질의응답 · 요약/Q&A · 대출반납 연계
- 추가 기능: **리뷰(별점 1~5 + 한줄)**, **예약**(대출 중인 책), **희망도서 구매 신청** — "재고 신청"의 의미를 물었더니 "둘 다(예약+구매신청)"로 확정
- **리뷰 추천 기능** 추가 (2026-09-13 민우 지시: "리뷰에도 추천 기능이 있어야해") — 👍 사용자당 리뷰별 1회, 추천 수 순 정렬. Claude가 "공감/도움돼요 버튼"으로 해석해 반영
- 리뷰 옵션 중 "텍스트만" / "리뷰 제외"는 버림

## UX 방향 (민우의 그림)

- 메인 페이지는 구글/네이버식 검색: 키워드 결과 리스트 + **상단 AI 검색 영역**
- **플로팅 AI 챗봇**: 채팅에서 바로 대출·재고 신청 실행 가능
- AI가 **네비게이션 버튼을 제안** (예: "리뷰 쓰러가기" → 해당 책 리뷰 폼으로 이동)
- 원칙: *"최대한 AI 에이전트를 통해 웹사이트 네비게이션이 편하게 + AI 기능을 적극 사용"*
- 기능별 분리 화면안, RAG 파이프라인안은 버림 (50권 규모에 벡터DB는 오버킬)

## 기술 선택

| 항목 | 결정 | 버린 대안 |
|---|---|---|
| 프레임워크 | **Nuxt** | Streamlit, FastAPI, Spring Boot, Node/React |
| AI | **Claude API** | OpenAI, Ollama, 모킹 |
| AI 프레임워크 | **LangChain.js 사용** (민우 지시) | SDK 직접 호출 |
| DB | **SQLite** | PostgreSQL, MySQL, JSON 파일 |
| 도서 데이터 | **알라딘 API로 수집 → 시드 DB 저장** | 수작업 시드, 카카오/네이버/구글 API |
| 사용자 | **이름 선택 로그인** (비밀번호 없음) | 이름 직접 입력, 이메일 로그인 |

## 코드 품질 지시사항 (민우)

1. LangChain을 사용할 것
2. **AI 챗봇 버튼은 로그인 상태에서만 활성화** — 비로그인 화면에는 없어야 함
3. API는 최대한 **RESTful**하게 설계
4. **JS 파일 하나에 몰아넣지 말 것** — 유지보수 쉽게 레이어 분리 (api → service → repository → db)
5. **전부 TypeScript일 것** — 서버·프론트·스크립트 예외 없음 ("명심해", 2026-09-13)
