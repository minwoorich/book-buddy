# 2026-09-16 장소 후기 — 카카오 리뷰 임베드 대신 자체 태그 후기

## 결정

민우 질문: "장소 메뉴에서 해당 카페에 대한 카카오 리뷰를 임베딩할 수는 없나?" → 조사 결과 불가, **자체 후기 기능**으로 대체하기로 함("내부적으로 리뷰 서비스 기능 하나 만들자. 너무 복잡하진 않고, 카페 리뷰 남기는 것도 최대한 간단하지만 이쁘게").

- **형식은 태그 칩 + 선택적 한 줄(A안).** 별점 없음. "조용해요 / 콘센트 있어요 / 자리 넓어요 / 오래 있기 좋아요 / 채광 좋아요 / 시끄러워요" 6개 고정. 입력 5초라 실제로 쌓이고, "책 읽기 좋은 자리" 정보라는 점에서 카카오 리뷰(커피 맛)와 성격이 다르다.
- **키는 카카오 장소 `id`.** 장소는 DB에 없는 실시간 검색 결과라 안정 키가 필요한데, 로컬 API 응답의 `id`가 그 역할. 지금까지 버리던 `id`·`place_url`을 `Place.kakaoId`·`placeUrl`로 살린다. 폴백 예시 4곳은 id가 없으니 후기 UI 숨김.
- **1인 1후기, 덮어쓰기(upsert).** 책 리뷰의 QA #18 규칙과 같다.
- **카드 안 인라인.** 모달·별도 페이지 없음. 집계 칩 최대 3개 + 최근 코멘트 2줄, 펼치면 칩 토글 + 한 줄 입력.

## 조사 결과 (카카오 쪽)

- 로컬 키워드 검색 응답 필드는 `id, place_name, category_*, phone, address_name, road_address_name, x, y, place_url, distance`가 전부 — **평점·리뷰 없음**. 지도 JS SDK에도 리뷰 API 없음.
- `place.map.kakao.com/{id}`는 현재 `X-Frame-Options`/`frame-ancestors`를 안 보내 iframe이 뜰 수는 있으나, 리뷰 위젯이 아닌 전체 페이지이고 비공식이라 언제든 막힐 수 있음. 시연 중 깨질 위험이 커서 제외.
- 내부 API(`place-api2.kakao.com`) 스크래핑은 약관 위반·불안정 — 제출작에 넣지 않음.

## 버린 대안

- **B. 별점 + 한 줄**: 익숙하지만 "커피 맛 4점"과 구분이 안 되고 카드에 숫자 하나만 남는다.
- **C. 칩 + 별점 둘 다**: "최대한 간단하게"와 어긋남.
- **후기 추천/좋아요·모아보기 페이지·사진·관리자 삭제·내 서재 연동**: 이번엔 안 함(YAGNI). 필요하면 다음에.
