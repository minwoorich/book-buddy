# 2026-09-16 시연용 게스트 선점 화면 (QR 접속 심사위원용)

## 결정

민우 요청: 발표 마지막에 QR(https://www.vnlibrary.com)을 띄워 심사위원들이 직접 접속하게 할 것. 문제는 ① 책벗은 로그인 필수 ② 한 계정을 여럿이 쓰면 서재·대출·대화가 뒤섞임 ③ 회원가입은 너무 오래 걸림. 그래서 "guest1~5를 미리 만들고 들어가면 바로 고르게, 누가 고른 자리는 다른 사람이 못 고르게".

- **`/login` 위에 게스트 카드 섹션을 얹는다.** 기존 이름/비밀번호 폼과 헤더의 "로그인" 버튼은 그대로 — 민우가 명시적으로 "로그인 버튼을 숨겨선 안 돼". 게스트 계정이 DB에 없으면 섹션 자체가 안 뜨므로 **시연 켜기/끄기 = 게스트 시드 유무**.
- **선점은 `guest_claims(user_id PK, token)`에 INSERT 한 줄.** PK 충돌이 곧 "이미 선점됨"(409)이라 동시에 눌러도 한 명만 성공. 화면은 3초 폴링으로 남의 선택을 회색 처리.
- **게스트는 토큰까지 맞아야 인증 통과.** `x-user-id`만 믿는 기존 모델에 `x-guest-token`을 더해 `optionalUser`가 게스트면 선점 토큰 일치를 확인. 이 덕에 "전체 해제"가 곧 강제 로그아웃이 된다(토큰 무효 → 401 → 기존 useApi 자동 로그아웃 경로).
- **해제 정책(민우 선택): 로그아웃 + 관리자 일괄 해제.** 자동 만료 타이머는 두지 않는다. 가만히 화면만 보는 게스트도 즉시 튕기도록 게스트 한정 10초 하트비트(`/api/guests/me`).

## 버린 대안

- **N분 자동 만료**: 시연 중 누가 생각보다 오래 쓰면 중간에 끊긴다. 발표자가 통제하는 편이 안전.
- **해제 시 게스트 계정 삭제·재생성(id 갈아서 무효화)**: 대출·리뷰 FK 정리가 따라와 복잡. 토큰 한 컬럼이 더 단순.
- **별도 `/demo` 경로**: 모든 "로그인 필요" 진입점(헤더·책벗 위젯·도서 상세)이 이미 `/login`으로 모이므로 그 자리에 얹는 게 자연스럽다.
