# 2026-09-15 반응형(모바일) 대응 방식

## 결정

민우 지시: "모든 페이지가 반응형이 적용돼야 해" — 데스크톱 전용이던 UI를 태블릿·모바일까지 대응한다.

- **브레이크포인트 2개**: 900px(태블릿, 2단 레이아웃을 1단으로) / 640px(모바일, 여백·글자·헤더 축소). 값은 `main.css`와 `useShelfColumns.ts`(`BP_TABLET`/`BP_MOBILE`)에서 같이 쓴다.
- **별도 모바일 페이지 없이 CSS 미디어쿼리 + 최소한의 JS**로 처리. 각 `.vue`의 `<style scoped>` 끝에 `@media` 블록을 추가하는 방식으로 기존 데스크톱 스타일은 손대지 않는다.
- **서가(선반) 칸 수는 JS로 결정**: 데스크톱 6/8칸 → 태블릿 4/5칸 → 모바일 3칸. 서가는 "표지 줄 → 선반 → 제목 줄"을 한 묶음으로 렌더하기 때문에 CSS만으로 칸 수를 바꾸면 선반이 줄 중간에 끼어든다. `useShelfColumns` 컴포저블이 `matchMedia`로 칸 수를 정하고 `chunk()`로 줄을 다시 나눈다.
- **관리자 표**: 열이 많은 표(최근 대출, QA 피드백)는 모바일에서 행을 카드처럼 세로로 쌓는 `.table.stack-sm` 유틸리티, 숫자 위주라 헤더 없이는 읽기 어려운 표(AI 호출 기록)는 `.table-scroll`로 가로 스크롤.
- **모바일 네비**: 로고·사용자 영역을 첫 줄, 메뉴는 가로 스크롤되는 둘째 줄. 햄버거 메뉴는 두지 않았다(항목 7개가 한 줄에 들어오고, 탭 한 번에 이동하는 편이 데모에 유리).
- **챗봇(책벗)**: 모바일에서는 전체 화면 패널로. QA 패널은 좌우 12px 여백 + z-index를 FAB보다 높게.

## 버린 대안

- **Tailwind/UI 프레임워크 도입**: 기존 CSS 변수 기반 에디토리얼 스타일을 전부 다시 써야 해 범위가 과함.
- **서가를 CSS `auto-fill` 그리드로만 처리**: 선반 위치가 깨져 서가 컨셉이 무너짐 → JS 칸 수 결정으로 대체.
- **관리자 페이지는 데스크톱 전용으로 제외**: "모든 페이지" 지시에 어긋나서 포함.

## 검증

Chrome DevTools Protocol로 390px/768px 뷰포트에서 로그인 상태로 전 페이지(관리자 포함)를 스크린샷하고 `scrollWidth > clientWidth`(가로 넘침)를 자동 검사 — 넘침 0건. 스크립트는 일회용이라 저장소에 넣지 않았다.
