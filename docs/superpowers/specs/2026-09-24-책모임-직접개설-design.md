# 책모임 직접 개설 — 설계서

작성 2026-09-24 · 상태: 사용자 검토 대기 · 전제 설계서 [[2026-09-20-책모임-design|책모임 설계서]](1~3단계 구현·배포 완료)

## 1. 왜

책모임은 지금 **에이전트만 만들 수 있다**(완독자 탐지 → 관리자 승인 → 초대). 사람이 "이 책으로 모이고 싶다"고 해도 방법이 없다. 이 설계는 사람이 시작하는 모임을 더한다 — 개설하고, 모집글을 쓰고, 사람을 모으고, 모임 안에서 이야기한다. 시작만 사람이 하고 그다음(시간 투표·장소 확정·리마인드·종료·후기 요청)은 에이전트 모임과 **같은 기계**를 탄다.

## 2. 결정 사항 (2026-09-24 브레인스토밍)

| 질문 | 결정 |
|---|---|
| 사람이 만든 모임의 성격 | **같은 모임, 시작만 사람이** — 별도 "방" 구조를 두지 않고 `clubs`를 확장 |
| 모집 방식 | **공개 모집 + 초대 둘 다** — 목록의 "모집 중"에서 누구나 참여(선착순), 개설자는 특정 사람을 초대할 수도 |
| 글쓰기 범위 | **모집글 + 모임 안 게시판** — 개설 때 제목·소개글, 상세 안에 참가자 전용 글·댓글. 피드 연동은 하지 않는다 |
| 참여 조건 | **없음, 완독자 표시만** — 그 책을 반납한 사람에게 "완독" 배지 |
| 관리자 승인 | **없음** — 만들면 즉시 모집 중. 관리자는 사후에 접을 수 있다 |
| 스팸 쿼터 | **사람 모임엔 없음** — 동시 참여·쿨다운·책 재개설 제한을 두지 않는다. 단 한 사람이 **모집 중인 사람 모임을 동시에 1개**만 열 수 있다 |
| 모집 종료 | **개설자가 닫되 안전망** — 모집 기간(3/7/14일, 기본 7) 만료 시 3명 이상이면 자동 조율, 미만이면 취소 |

## 3. 생애주기

사람 모임은 `origin = 'user'`. 만들면 곧바로 `inviting`(화면 표기 "모집 중"). 이후는 기존과 같다.

```
개설 ──즉시──> 모집 중(inviting) ──개설자 "모집 마감"(3명↑) 또는 기간 만료(3명↑)──> 조율중(scheduling) ──> 확정 ──> 종료 → 후기 요청
                    │ 기간 만료(3명 미만) · 개설자 "모임 접기" · 관리자 접기
                    ↓
                취소(canceled)
```

| 전이 | 사람 모임 | 에이전트 모임(변경 없음) |
|---|---|---|
| → inviting | 개설 즉시. `recruit_until` = 개설 시각 + 모집 기간(일)의 23:59:59Z | 관리자 승인 |
| inviting → scheduling | 호스트가 "모집 마감"(수락 3명 이상) **또는** `recruit_until` 경과 시 자동(3명 이상) | 수락 3명이 되는 즉시 자동 |
| inviting → canceled | `recruit_until` 경과 시 3명 미만 ("모집 기간에 3명이 안 모였어요") · 호스트 "모임 접기" · 관리자 접기 | 3일 내 미달 · 3명이 불가능해지는 즉시 |
| scheduling 이후 | 공통 (설계서 §3) | 공통 |

**자동 전이를 하지 않는 이유.** 공개 참여가 있으니 "3명이 불가능하다"는 판정이 없고, 5명 정원이 사흘 만에 차도 호스트가 더 기다리고 싶을 수 있다. 개설자가 닫고, 기한이 유령 모임을 막는다.

`scheduling` 진입 시 **AI 아젠다를 이때 만든다**(에이전트 모임은 제안 시점에 이미 있으므로 `agenda`가 비어 있을 때만). 입력은 수락자들이 그 책에 쓴 리뷰. 리뷰가 하나도 없으면 기존 `fallbackAgenda`(일반 질문 3개). 실패 규칙은 기존과 같다(폴백 + 0토큰 `ai_usage` 행).

## 4. 스키마

`clubs`에 열 6개 추가(`ALTER TABLE`, `PRAGMA table_info` 가드, 백필 없음 — 기존 행은 전부 `agent`):

| 열 | 타입 | 뜻 |
|---|---|---|
| `origin` | TEXT NOT NULL DEFAULT 'agent' CHECK IN ('agent','user') | 누가 시작했나 |
| `created_by` | INTEGER REFERENCES users(id) | 개설자(사람 모임만) |
| `title` | TEXT | 모임 제목(사람 모임만; 없으면 화면이 『책』 책모임으로) |
| `description` | TEXT NOT NULL DEFAULT '' | 모집글 |
| `capacity` | INTEGER NOT NULL DEFAULT 5 | 정원 3~6 |
| `recruit_until` | TEXT | 모집 마감(ISO, 앱이 씀) |

새 테이블:

```sql
CREATE TABLE IF NOT EXISTS club_posts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  club_id INTEGER NOT NULL REFERENCES clubs(id),
  user_id INTEGER NOT NULL REFERENCES users(id),
  parent_id INTEGER REFERENCES club_posts(id),   -- 댓글이면 부모 글. 한 단계만
  body TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now')));
CREATE INDEX IF NOT EXISTS idx_club_posts_club ON club_posts(club_id, created_at);
```

타입: `Club`에 `origin: 'agent' | 'user'`, `createdBy: number | null`, `title: string | null`, `description: string`, `capacity: number`, `recruitUntil: string | null`. `ClubMember`에 `completed: boolean`(그 책을 반납한 적 있음). 새 `ClubPost { id, clubId, userId, userName, department, parentId, body, createdAt, replies?: ClubPost[] }`.

## 5. 모집·참여·초대

### 5.1 개설 `POST /api/clubs` → `Club`

입력 `{ bookId, title, description, capacity, recruitDays }`.
- `bookId` 존재해야 함. `title` 1~40자(기본값은 화면이 채움: "『책』 함께 읽기"). `description` 0~1000자. `capacity` 3~6. `recruitDays` ∈ {3, 7, 14}.
- 개설자가 **이미 `inviting` 상태의 사람 모임을 호스트로 갖고 있으면 400** "모집 중인 모임은 하나만 열 수 있어요".
- 개설자는 `host`·`accepted`로 들어간다. `status = 'inviting'`, `match_score = 0`, `match_reason = ''`, `agenda = '[]'`, `candidate_slots = '[]'`, `invite_expires_at = NULL`(사람 모임은 `recruit_until`을 쓴다).
- 알림 없음(개설자 본인뿐).

### 5.2 공개 참여 `POST /api/clubs/:id/join` → `Club`

- 조건: `origin = 'user'` · `inviting` · 수락 인원 < `capacity` · 아직 멤버가 아니거나 `declined`였던 사람(재참여 허용). `invited` 상태인 사람이 누르면 초대 수락과 같게 처리(`respond(accept)` 경로).
- 결과: `member`·`accepted`. 알림: 호스트에게 `club_joined` "○○님이 참여했어요 (3/5)".
- 정원이 차면 400 "정원이 찼어요".

### 5.3 참여 취소 `DELETE /api/clubs/:id/join`

- `inviting` 동안만, `member`만(호스트는 접기를 써야 한다). 행 삭제(다시 참여 가능). 호스트에게 `club_left`.

### 5.4 초대 `POST /api/clubs/:id/invite { userIds: number[] }` → `Club`

- 호스트만 · `inviting`만 · 이미 멤버인 사람은 건너뜀 · 초대 수 + 수락 수 ≤ `capacity`를 넘으면 400 "정원보다 많이 초대할 수 없어요".
- `invited` 행 생성 → 기존 `club_invite` 알림 문구 그대로("○○님이 『책』 모임에 초대했어요"). 응답 기한은 `recruit_until`.
- 초대 응답(`respond`)은 **사람 모임에서 자동 전이를 하지 않는다** — 수락해도 `inviting` 유지, 거절해도 "불가능" 취소 분기를 타지 않는다.

### 5.5 모집 마감 `POST /api/clubs/:id/close-recruiting` → `Club`

- 호스트만 · `inviting`만 · 수락 3명 이상(400 "3명이 모여야 시간을 잡을 수 있어요").
- 미응답 `invited`는 `declined`로 닫는다(수락자만 조율에 참여 — 기존 "inviting 이외 상태는 수락자만" 규칙과 정합).
- 기존 `enterScheduling(club, now)` 호출 → 슬롯 생성·`club_vote_request` 알림·아젠다 생성(§3).

### 5.6 모임 접기 `POST /api/clubs/:id/withdraw`

- 호스트만 · `inviting`만 → `canceled`, `canceled_reason = '개설자가 모임을 접었어요'`. 수락자·미응답 초대자에게 `club_canceled`. 관리자 접기는 **신규** `POST /api/admin/clubs/:id/cancel`(관리자만, `done`·`canceled`가 아닌 모든 모임 → `canceled` "관리자가 모임을 닫았어요" + 같은 알림) — 지금은 관리자가 진행 중 모임을 닫을 경로가 없다(승인 큐의 거절은 `proposed`만).

### 5.7 기한 처리 (`club:deadlines`, 00:00Z)

`expireInvites(now)`에 사람 모임 분기: `origin = 'user'` · `inviting` · `recruit_until < now` →
- 수락 ≥ 3: `invited`를 `declined`로 닫고 `enterScheduling`.
- 수락 < 3: `canceled` "모집 기간에 3명이 안 모였어요" + 수락자·초대자에게 `club_canceled`.
에이전트 모임 분기는 그대로. 반환값 `handled`에 같이 센다.

### 5.8 완독 표시

`ClubMember.completed` = 그 사람이 그 책을 반납한 `loans` 행이 있음(기간 제한 없음). 카드·상세 참가자 칩에 "완독" 배지, 카드 요약에 "완독 2 · 읽는 중 1"(읽는 중 = 지금 대출 중).

### 5.9 에이전트와의 경계

- 매처의 **busy**(진행 중 모임에 속한 사람)는 origin을 가리지 않는다 → 사람 모임 참가자는 그동안 초대받지 않는다(현재 쿼리가 이미 그렇다; 테스트로 고정).
- **cooled**(종료 후 4주)와 **책 재개설 금지**(3개월)도 origin을 가리지 않는다 — 방금 사람들이 모였던 책·사람을 에이전트가 곧바로 다시 부르지 않는 게 맞다.
- 반대로 사람 모임 개설에는 어떤 쿼터도 적용하지 않는다(§2). 사람이 에이전트 모임에 참여 중이어도 사람 모임을 열 수 있다.

## 6. 게시판

- `GET /api/clubs/:id/posts` → `ClubPost[]`(글 최신순, 각 글에 `replies` 시간순). **`accepted` 참가자만**(호스트 포함). `invited`·비멤버 403.
- `POST /api/clubs/:id/posts { body, parentId? }` → `ClubPost`. `accepted` 참가자만. `body` 1~2000자(trim). `parentId`가 있으면 같은 모임의 **최상위 글**이어야 한다(댓글의 댓글 400). `done`·`canceled`에서는 400 "끝난 모임이에요"(읽기는 됨).
- `DELETE /api/clubs/:id/posts/:postId` — 작성자 또는 호스트. 글을 지우면 댓글도 같이(하드 삭제).
- 알림 `club_post`: 최상위 글이 올라오면 작성자를 뺀 `accepted` 참가자에게. **같은 모임은 하루(KST) 1건** — 기존 `notificationRepo.has(userId, link)` dedup을 그대로 쓰기 위해 link에 KST 날짜를 넣는다: `/clubs/:id?posts=YYYY-MM-DD`(화면은 `posts` 쿼리 값을 무시하고 게시판으로 스크롤만). 댓글은 알림 없음.
- 에이전트 모임에도 같은 게시판이 붙는다(토론 질문 아래 "이야기").

## 7. 화면

### 7.1 `/clubs` 목록
- 상단 우측 "모임 만들기" 버튼 → `/clubs/new`.
- 새 구획 **"모집 중"**: 모든 사람 모임 `inviting`(내 참여 여부 무관), 마감 임박순. 카드: 제목 · 『책』 · 개설자 이름·부서 · "3/5명 · D-4 · 완독 2" · 소개글 첫 줄 · 버튼(미참여: "참여하기" / 참여 중: "참여 중" / 정원 참: "정원 마감" / 호스트: "내 모임").
- 기존 구획(초대·응답 필요·진행 중·지난)은 그대로. 내가 참여한 사람 모임은 "진행 중"에도 나타난다(중복 노출 허용 — 모집 중 구획은 발견용, 진행 중은 내 것).

### 7.2 `/clubs/new` 개설 폼
책 검색(`/api/books?query=`, 표지·제목·저자 목록에서 하나 선택) → 제목(기본값 채움) → 소개글(textarea) → 정원(3~6 셀렉트, 기본 5) → 모집 기간(3/7/14일 라디오, 기본 7) → "모임 열기". 성공 시 `/clubs/:id`. 400 문구는 alert(기존 관례).

### 7.3 `/clubs/:id` 상세
- 사람 모임이면 헤더가 **제목**, 부제가 『책』 · 개설자 · 소개글. 에이전트 모임은 지금처럼(『책』 책모임 · matchReason).
- 모집 중: "3/5명 · 9/30(수)까지 모집" · 버튼 — 미참여자 "참여하기", 참가자 "참여 취소", 호스트에겐 "초대하기"(이름 검색 모달, `/api/users` 재사용, 여러 명 선택) · "모집 마감 → 시간 잡기"(3명 미만이면 비활성 + 이유) · "모임 접기"(confirm).
- 참가자 칩에 "완독" 배지. 토론 질문은 `scheduling` 이후에만(모집 중엔 "모집이 끝나면 토론 질문을 만들어 드려요").
- 하단 **"이야기"** 게시판: 글 목록(최신 위) · 댓글 · 입력창(참가자만; 초대만 받은 사람에겐 "참여하면 이야기를 볼 수 있어요"). 끝난 모임은 읽기만.
- `?posts=` 쿼리로 들어오면 게시판으로 스크롤.

### 7.4 관리자
승인 큐는 그대로(에이전트 제안만). 기존 `ClubProposalQueue` 아래에 작은 구획 **"진행 중인 모임"**(`inviting`·`scheduling`·`confirmed` 전부, `GET /api/admin/clubs`): 제목 · 『책』 · origin 배지("사람"/"에이전트") · 상태 · 인원 · "닫기" 버튼(confirm → §5.6 관리자 접기).

## 8. 알림 (신규 3종, 기존 인프라)

| type | 받는 사람 | 문구 | link |
|---|---|---|---|
| `club_joined` | 호스트 | "○○님이 『책』 모임에 참여했어요 (3/5)" | `/clubs/:id` |
| `club_left` | 호스트 | "○○님이 참여를 취소했어요 (2/5)" | `/clubs/:id` |
| `club_post` | 작성자 제외 수락자, 모임당 하루 1건 | "『책』 모임에 새 글이 올라왔어요" | `/clubs/:id?posts=YYYY-MM-DD` |

기존 재사용: `club_invite`(초대), `club_canceled`(접기·기간 만료), `club_vote_request`(모집 마감 → 조율 시작).

## 9. 코드 배치

- `server/services/clubRecruitService.ts` — 개설·참여·취소·초대·모집 마감·접기·`expireRecruiting(now)`(§5.7). `clubService.expireInvites`가 이걸 호출해 합산.
- `server/services/clubPostService.ts` + `server/repositories/clubPostRepo.ts` — 게시판.
- `clubRepo` 추가: `create(input)`, `listRecruiting(nowIso)`, `hostingRecruitingCount(userId)`, `removeMember(clubId, userId)`, `declinePending(clubId)`, `completedUserIds(bookId, userIds)`, `currentlyReadingUserIds(bookId, userIds)`.
- `clubService` 수정(작게): `respond`의 자동 전이·불가능 취소를 `origin === 'agent'`로 한정, `enterScheduling`에서 `agenda.length === 0`이면 아젠다 생성(에이전트 모임의 `clubMatcher`는 그대로 제안 시점에 생성).
- `shared/utils/clubTitle.ts`에 `clubTitle(club: Pick<Club, 'origin' | 'title' | 'bookTitle'>)`: 사람 모임은 `title`, 아니면 `『책』 책모임` — 카드·상세·알림·ics·달력이 같은 함수를 쓴다(서버·화면 공용이라 `shared`).
- API: `POST /api/clubs`, `POST|DELETE /api/clubs/[id]/join`, `POST …/invite`, `POST …/close-recruiting`, `POST …/withdraw`, `GET|POST …/posts`, `DELETE …/posts/[postId]`, `GET /api/clubs/recruiting`, 관리자 `GET /api/admin/clubs`·`POST /api/admin/clubs/[id]/cancel`. (`clubs/recruiting`은 `clubs/[id]`보다 정적 라우트가 우선 — 3단계 `upcoming-places`에서 확인한 규칙.)
- 화면: `app/pages/clubs/new.vue`(신규), `clubs/index.vue`·`clubs/[id].vue`·`components/club/Card.vue` 수정, `components/club/PostBoard.vue`·`InviteDialog.vue`(신규).

## 10. 테스트

서비스 테스트(vitest, 기존 인메모리 DB 패턴):
- 개설: 유효성(정원·기간·제목 길이) · 모집 중 1개 상한 · 호스트 accepted · `recruit_until` = 23:59:59Z.
- 참여: 선착순 정원 · 중복 400 · `declined` 재참여 · `invited`가 누르면 수락 처리 · 호스트 알림.
- 취소: 호스트 불가 · `inviting` 밖 400.
- 초대: 비호스트 403 · 정원 초과 400 · 기존 멤버 건너뜀 · `club_invite` 발송.
- 응답: 사람 모임에서 3명 수락해도 `inviting` 유지 · 거절해도 취소 안 됨. 에이전트 모임 기존 테스트 전부 유지.
- 마감: 2명이면 400 · 3명이면 scheduling + `invited` → `declined` + 슬롯·투표 알림 · 아젠다 생성(리뷰 있음/없음 폴백).
- 기한: `recruit_until` 경과 시 3명↑ 자동 조율 / 미만 취소 + 알림 · 하루 두 번 실행해도 멱등.
- 접기: 호스트만 · 알림.
- 매처: 사람 모임 참가자가 busy로 제외됨 · 사람 모임의 책이 책 쿨다운에 잡힘.
- 게시판: `invited` 403 · 댓글의 댓글 400 · 끝난 모임 쓰기 400 · 작성자/호스트만 삭제 · 글 삭제 시 댓글 삭제 · `club_post` 하루 1건.
- `clubTitle` 순수 함수.
화면은 헤드리스 Chrome 시각 확인(개설 → 모집 중 카드 → 다른 사람 참여 → 초대 → 마감 → 투표 화면 → 게시판).

## 11. 하지 않는 것

- 피드 연동, 이미지 첨부, 글 수정(삭제 후 다시 씀), 댓글의 댓글, 좋아요.
- 사람 모임에 대한 관리자 승인·쿼터.
- 정원 6 초과, 모집 기간 자유 입력.
- 모집 중 모임의 시간·장소 미리 정하기(조율은 기존 흐름 그대로).

## 12. 단계 분할

한 계획으로 간다(태스크 8~10개). 순서: 스키마·타입 → clubRepo → clubRecruitService(개설·참여·초대·마감·접기·기한) → clubService 분기·아젠다 이동 → API → 게시판(repo·service·API) → 화면(new·목록·상세·카드·게시판·초대) → 관리자 표시 → 시각 확인·문서.
